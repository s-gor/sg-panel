# Changelog

## 0.10.0 RC34 — безопасные обновления из интерфейса

- добавлена вкладка `Maintenance → Updates` с установленной и последней версиями, ручной проверкой, запуском обновления и живым журналом;
- документация подробно объясняет результаты проверки версии, недоступную кнопку при отсутствии обновлений, кратковременную потерю связи и итоговые состояния «Готово»/«Восстановлено»;
- updater работает отдельной systemd-операцией, использует lock и не допускает параллельного запуска;
- перед изменением сервера создаётся полная страховочная копия приложения, SQLite, env, Xray, WARP, DNS, Traffic Rules, Outbounds, Nginx, заглушки, systemd и сведений о сертификатах;
- после установки проверяются локальный health SG-Panel, точная версия, `xray run -test`, Xray, Nginx и активные таймеры;
- при ошибке автоматически возвращается предыдущая рабочая версия;
- добавлен ручной updater из проверенного локального исходного кода;
- документация объясняет первый переход с RC30, принятие рекомендуемых значений установщика нажатием Enter и совместную работу VLESS и HTTPS/fallback на `443/tcp`;
- RC31, RC32 и RC33 не используются.

## 0.10.0 RC30 — Hysteria 2, Clients & Traffic Studio

- на реальном EC2 подтверждена цепочка `Клиент → Hysteria 2 → Xray → WARP → Интернет`; в руководство добавлены пошаговое включение, проверка Default Outbound и быстрый возврат на `direct`;
- документация приведена в соответствие с интерфейсом: четыре доступных Inbound-профиля, выбор четырёх XHTTP modes, Xray defaults для XMUX, точное описание DNS и внутреннего порта `8443`;
- полностью переработаны публичный README и комплект пользовательской документации: установка, интерфейс, Clients, ссылки и подписки, четыре доступных Inbound-профиля, Traffic Rules, Outbounds, DNS, WARP, HTTPS/fallback, Security, Maintenance, диагностика и удаление;
- добавлен полный `FULL-UNINSTALL-SG-PANEL.sh --yes` для выделенного тестового сервера: семь этапов, зелёная живая строка прогресса, время выполнения и финальная проверка;
- полный uninstall удаляет SG-Panel, Xray, WARP, Nginx, Certbot, сертификаты, fallback/заглушку, резервные копии и swap, но не затрагивает SSH, сеть и Security Group;
- добавлена локальная HTTPS-заглушка/fallback для обычного трафика на 443 при сохранении рабочих RAW/REALITY, XHTTP/REALITY, XHTTP/TLS и Hysteria 2;
- знак на странице входа приведён к единому логотипу `SG`;
- Reality SNI больше не используется как домен TLS-сертификата Hysteria 2;
- кнопка сброса трафика выбранного клиента перенесена из скрытого технического блока в основные действия карточки клиента;
- кнопка общего сброса трафика перенесена в верхнюю панель Clients & Traffic Studio;
- добавлены подробные подтверждения: сброс не удаляет пользователей, UUID/Auth, ссылки, подписки и конфигурации;
- после сброса показывается отдельное понятное уведомление;
- дата последнего сброса сохраняется и отображается в технических данных клиента;
- релиз объединяет все изменения после публичного RC9: Hysteria Studio, установка сначала по IP без обязательного домена, позднее включение HTTPS и новый центр управления клиентами;
- сохранены исправление Stats API из RC29, долговременная SQLite-история и все функции Clients & Traffic Studio.

## 0.10.0 RC29 — Traffic Activation & Safe Upgrade

- исправлена главная причина нулевого трафика после Speed Test: Xray Stats API теперь включён по умолчанию для новых серверов и однократно активируется при обновлении существующей базы;
- обновление после миграции безопасно пересобирает и применяет `config.json`, поэтому `api`, `stats` и пользовательская `policy` действительно появляются в работающем Xray;
- перед изменением сохраняется отдельная копия `/usr/local/etc/xray/config.json`; при ошибке возвращаются прежние файлы панели, SQLite и конфигурация Xray, затем службы перезапускаются;
- добавлена строгая проверка `collect-traffic --online --strict`, которая завершает установку с ошибкой, если Stats API выключен или недоступен;
- повторный `init-db` не включает Stats API снова после того, как администратор позднее отключил его вручную;
- таймер продолжает собирать трафик раз в минуту без строгого режима, чтобы временная недоступность API не блокировала последующие попытки;
- добавлены регрессионные тесты миграции RC28 → RC29, новых установок, безопасного применения и проверки коллектора;
- сохранены все функции Clients & Traffic Studio, Hysteria Studio и Xray `v26.5.9`.

## 0.10.0 RC26 — Hysteria Studio

- страница Hysteria 2 превращена в отдельный центр управления: статус профиля, публичная UDP-точка, версия Xray, TLS, пользователи и локальная готовность отображаются в одном блоке;
- добавлены безопасные пресеты производительности: Автоматически, Мобильная сеть, Высокая скорость, Ограниченный сервер и Пользовательский;
- добавлены параметры QUIC/FinalMask: congestion control, BBR profile, Brutal Upload/Download, KeepAlive, max idle timeout, Path MTU Discovery, maximum incoming streams, receive windows и debug;
- добавлен UDP port hopping с проверкой отдельных портов и диапазонов, интервалом не меньше пяти секунд и генерацией совместимой Hysteria URI;
- HTTP/3 masquerade расширена до четырёх режимов: стандартная 404, собственный HTML, статический каталог и proxy URL; для proxy доступны Rewrite Host и проверка сертификата, для HTML — статус и пользовательские заголовки;
- параметры Hysteria сохраняются в SQLite, проходят обязательную серверную валидацию, включаются в Current JSON и восстанавливаются при синхронизации полного config.json;
- успешные уведомления больше не перекрывают верхнюю панель: они показываются под вкладками, сокращены и автоматически исчезают через семь секунд;
- добавлена отдельная страница «Полная проверка Hysteria 2»: DNS, TLS-файлы и срок сертификата, `xray run -test`, структура generated config, состояние systemd, UDP listener, пользователи, port hopping и анализ последних строк журнала; внешняя доступность UDP честно помечается как требующая реального клиентского подключения;
- сохранены validate-first, резервная копия, `xray run -test`, проверка службы и автоматический откат при неудачном применении;
- подготовлен фундамент для следующего этапа Multi-Inbound, но RC26 по-прежнему использует один активный основной Inbound.

## 0.10.0 RC25 — draft/active inbound states and immediate Hysteria settings
