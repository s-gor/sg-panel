# SG-Panel v0.10.0-rc59

RC59 собран на основе `058-SG-Panel-RC58.zip`. Основная задача релиза — убрать ручной перенос параметров при создании пользовательского VLESS Outbound и подготовке каскада между двумя SG-Panel.

## Импорт VLESS-ссылки

В `Routing → Outbounds → Добавить выход` появился отдельный блок **«Импорт из VLESS-ссылки»**.

Пользователь копирует готовую `vless://`-ссылку на удалённой панели, вставляет её и нажимает **«Разобрать и заполнить»**. Панель автоматически переносит:

- адрес и порт;
- UUID;
- RAW/TCP или XHTTP;
- REALITY или TLS;
- Flow / XTLS Vision;
- Server Name / SNI;
- fingerprint;
- Reality Public Key;
- Short ID и Spider X;
- XHTTP Host, Path и Mode;
- ALPN и `allowInsecure` для TLS.

Для ссылки с названием `Cascade-CC1-to-CC2` предлагается технический тег `cascade-cc2`. Тег и понятное название можно изменить до создания.

## Безопасность и validate-first

- Полная ссылка не сохраняется в SQLite.
- После успешного разбора поле со ссылкой очищается.
- Endpoint импорта только разбирает и проверяет значения; запись Outbound не создаётся.
- Создание выполняется отдельным подтверждением через существующую validate-first процедуру, `xray run -test`, применение и rollback.
- Некорректная или неподдерживаемая ссылка отклоняется целиком с понятной причиной.

## Поддерживаемые комбинации

- VLESS RAW/TCP + REALITY;
- VLESS XHTTP + REALITY;
- VLESS XHTTP + TLS.

## Что не изменено

- тихий установщик и rollback RC58;
- WARP Routing и подробная проверка RC56–RC57;
- Cluster и SG-Node;
- managed profile v2;
- существующие клиенты, UUID, ключи, сертификаты и правила;
- SG Client.

RC59 предназначен для продолжения натурной проверки каскада `CC1 → CC2 → Internet`.
