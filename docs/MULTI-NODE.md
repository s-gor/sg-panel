# SG-Panel Cluster и SG-Node

Документ относится к `Preview 9 · FIX40 · Hotfix 18`.

## Что такое Cluster

Один Controller хранит общую клиентскую базу и управляет дополнительными SG-Node. На Node работают Agent и Worker; Xray и Nginx остаются локальными службами сервера.

```text
Cluster Controller
├── центральная база клиентов и deployments
├── SG-Node 1 · Agent + Worker + Xray/Nginx
└── SG-Node 2 · Agent + Worker + Xray/Nginx
```

## Подключение: одна кнопка и одна команда

Пользователь не выбирает тип сервера и не выполняет отдельные этапы установки и регистрации.

1. Откройте **Cluster**.
2. Введите понятное имя, например `Paris-Node`.
3. Нажмите **«Подключить SG-Node»**.
4. Скопируйте единственную команду.
5. Выполните её через SSH на нужном Ubuntu-сервере.

Команда сама определяет состояние машины.

### Чистая Ubuntu

Устанавливаются Node runtime, Agent, Worker, Xray, Nginx, Certbot и необходимые зависимости. Затем сервер сразу регистрируется на Controller и отправляет подтверждённый heartbeat.

### SG-Panel уже установлена

Сохраняются без изменений:

- веб-панель и `xpanel-web`;
- Nginx и внешний HTTP/HTTPS-доступ;
- Xray и действующий `config.json`;
- существующие клиенты и настройки;
- текущие системные пакеты.

Устанавливаются или обновляются только SG-Node Agent, Worker и служебные каталоги. После этого выполняется регистрация на Controller.

Если скрипт обнаруживает непонятную или опасную старую установку, он прекращает работу до изменений.

## Что должно появиться после выполнения

Карточка автоматически перейдёт в состояние **«В сети»** и покажет:

- публичный адрес;
- количество клиентов;
- CPU, RAM и диск;
- подтверждённый heartbeat.

Технические версии, GeoFiles, ручные операции, журнал и обслуживание находятся в свёрнутом разделе **«Дополнительно»**.

## Следующий шаг

Если на Controller уже есть активные клиенты, нажмите в карточке Node:

**«Развернуть профиль и клиентов»**

Controller соберёт единую конфигурацию, Node выполнит `xray run -test` и применит её атомарно. При ошибке рабочая конфигурация сохраняется или восстанавливается из резервной копии.

Если клиентов ещё нет, сначала откройте **Clients** и создайте клиента.

## Повторное подключение

В карточке Node откройте **«Дополнительно»** и нажмите **«Создать новую команду подключения»**. Новая одноразовая команда заменит прежнюю регистрацию после успешного heartbeat.

## Проверка служб на Node

```bash
systemctl is-active sg-node-agent sg-node-worker nginx xray
```

Для сервера с полной SG-Panel собственная панель должна оставаться доступной после подключения Node.

Журналы:

```text
/var/log/sg-node-full-install.log
/var/log/sg-node-connect.log
```

## Безопасность

- Не публикуйте команду подключения: она содержит одноразовый enrollment token.
- Agent не получает интерактивный shell.
- Привилегированные операции выполняет отдельный Worker по ограниченной очереди заданий.
- Controller принимает статус **«В сети»** только после настоящего heartbeat.
- Firewall автоматически не изменяется.
