# SG-Panel Cluster и SG-Node

Документ относится к версии `v0.10.0-rc70`.

## Что такое Cluster

В кластере есть один **Cluster Controller** с полной SG-Panel и дополнительные серверы **SG-Node** без второй административной панели.

```text
Cluster Controller
├── SG-Panel и центральная база
├── SG-Node 1: Agent + Worker + Xray/Nginx runtime
├── SG-Node 2: Agent + Worker + Xray/Nginx runtime
└── SG-Node 3: Agent + Worker + Xray/Nginx runtime
```

Правильный порядок всегда один:

```text
1. Подготовить чистую Ubuntu
2. Добавить карточку SG-Node
3. Подключить установленную SG-Node
4. Проверить статус и heartbeat
5. Развернуть первый профиль
```

Полная установка и подключение — разные операции:

- команда **полной установки SG-Node** ставит runtime и переводит сервер в `ready_to_connect`, но не содержит токена;
- команда **подключения** связывает уже подготовленный сервер с конкретной карточкой Cluster и использует одноразовый токен.

## Перед началом

Нужно подготовить:

- работающий Cluster Controller с SG-Panel;
- отдельный сервер с чистой поддерживаемой Ubuntu LTS и доступом `sudo`;
- исходящий доступ Node к адресу и порту Controller;
- открытый клиентский порт `64441/tcp` на Node для первого профиля;
- понятное имя Node, например `FR2 Frankfurt`.

На Node заранее не требуются ручные `apt update`, `curl`, `unzip` или установка Xray.

## Шаг 1. Подготовить чистую Ubuntu как SG-Node

1. На Controller откройте **Cluster**.
2. В карточке **«Шаг 1. Подготовить чистую Ubuntu как SG-Node»** нажмите **«Скопировать команду полной установки SG-Node»**.
3. Подключитесь по SSH к чистому серверу Node.
4. Вставьте и запустите скопированную однострочную команду.
5. Дождитесь успешного завершения и состояния `ready_to_connect`.

Команда самодостаточна: при необходимости устанавливает bootstrap-зависимости, затем ставит:

- SG-Node Agent;
- SG-Node Worker;
- Xray Runtime;
- Nginx;
- Certbot;
- системные и диагностические зависимости;
- systemd-службы, каталоги и журналы.

Она не создаёт карточку Node, не использует enrollment token и не разворачивает клиентский профиль.

После подготовки Xray и Nginx могут быть остановлены. В интерфейсе это должно отображаться нейтрально как **«ожидает первого профиля»**.

Проверка готовности на Node:

```bash
sudo cat /etc/sg-node/install.env
```

Ожидаемая строка:

```text
STATUS=ready_to_connect
```

Основной журнал установки:

```text
/var/log/sg-node-full-install.log
```

## Шаг 2. Добавить подготовленную SG-Node

1. Вернитесь в **Cluster** на Controller.
2. Нажмите **«Добавить подготовленную SG-Node»**.
3. Заполните:
   - имя сервера;
   - роль;
   - локацию;
   - публичный IP или домен — необязательно;
   - назначение — необязательно.
4. Нажмите **«Создать карточку и новый токен»**.
5. Откроется карточка созданной Node с одноразовой командой подключения.

Enrollment token действует 30 минут и используется один раз. Создание новой команды отзывает предыдущий неиспользованный токен этой карточки.

Не публикуйте команду подключения и не помещайте её в общедоступные журналы.

## Шаг 3. Подключить установленную SG-Node

1. На странице карточки Node найдите блок **«Шаг 3 · Подключение SG-Node»**.
2. Нажмите **«Скопировать команду подключения»**.
3. Вернитесь в SSH уже подготовленной Node.
4. Запустите скопированную команду.
5. Дождитесь успешной регистрации и подтверждённого heartbeat.

Команда подключения:

1. проверяет `/etc/sg-node/install.env`;
2. принимает состояния `ready_to_connect` или `connected`;
3. обновляет Agent и Worker из текущего Controller;
4. использует одноразовый enrollment token;
5. запускает Worker и Agent;
6. получает постоянный Agent token;
7. отправляет настоящий heartbeat;
8. завершается только после подтверждения Controller.

Если полная установка не выполнена, команда останавливается с сообщением:

```text
SG-Node ещё не подготовлена. Сначала выполните полную установку SG-Node.
```

Журнал подключения:

```text
/var/log/sg-node-connect.log
```

После принятого heartbeat карточка автоматически обновляется:

- одноразовая команда исчезает;
- этапы подключения и статуса отмечаются выполненными;
- появляется статус **«Нода подключена»**;
- шаг первого профиля разблокируется.

Повторно нажимать **«Создать новую команду»** после успешного heartbeat не нужно.

## Шаг 4. Проверить статус

Карточка подключённой Node должна показать:

- состояние **«В сети»**;
- SG-Node Agent — версия и **«работает»**;
- SG-Node Worker — версия и **«работает»**;
- Heartbeat — **«Только что»** или близкое время;
- публичный IPv4 или домен;
- платформу и архитектуру;
- версии Xray и Nginx;
- CPU, RAM, диск и Load.

До первого профиля нормальны статусы:

```text
Xray: ожидает первого профиля
Nginx: ожидает первого профиля
Серверная схема: Первый профиль ещё не развёрнут
```

Agent пытается определить адрес через окружение, EC2 IMDS, системный FQDN и адрес запроса. Если адрес не определился либо используется нестандартный NAT, укажите его вручную в карточке и нажмите **«Сохранить карточку»**.

## Шаг 5. Развернуть первый профиль

Перед развёртыванием разрешите на Node входящий порт:

```text
64441/tcp
```

В AWS EC2 это делается в Security Group Node. Порт `64441` открывается на Node, а не на Controller.

После состояния **«В сети»**:

1. Найдите блок **«Шаг 5 · Первый профиль»**.
2. Выберите существующего клиента Controller.
3. Проверьте публичный IP или домен Node.
4. Оставьте порт `64441`, если не требуется другой свободный TCP-порт.
5. Проверьте Reality target и Server Name / SNI.
6. Нажмите **«Проверить и развернуть»**.
7. Дождитесь успешного завершения задания.

Стартовая схема:

```text
Профиль:     VLESS REALITY
Transport:   RAW/TCP
Порт:        64441/TCP
Flow:        xtls-rprx-vision
Fingerprint: firefox
```

Worker выполняет:

1. проверку разрешённой структуры задания;
2. проверку SHA-256;
3. `xray run -test`;
4. резервную копию;
5. атомарную замену `config.json`;
6. включение и запуск Xray;
7. проверку службы;
8. rollback при ошибке.

Nginx для первого RAW/TCP REALITY-профиля не требуется и не должен занимать клиентский порт `64441`.

## После развёртывания

Проверьте:

1. Xray на Node имеет состояние **«работает»**.
2. В карточке появилась активная серверная схема.
3. Задание завершилось без ошибки.
4. Порт `64441/tcp` доступен извне.
5. Клиентская ссылка содержит адрес Node, порт `64441`, Flow `xtls-rprx-vision` и fingerprint `firefox`.
6. Реальное клиентское подключение работает.

## Повторное подключение

Кнопка **«Создать новую команду»** нужна только для:

- повторной регистрации;
- переноса Node;
- замены или ротации токена;
- восстановления утраченной связи после удаления регистрационных данных.

Она не нужна для обычного heartbeat, перезапуска Xray или развёртывания профиля.

После создания новой команды появляется блок **«Переподключить ноду»**. Новый enrollment token заменяет предыдущий неиспользованный токен. После успешной регистрации прежний постоянный Agent token становится недействительным.

Ручное редактирование `/etc/sg-node/agent.json` не требуется.

## Отключить ноду, удалить карточку или удалить Agent

Это три разные операции.

### «Отключить ноду»

- Controller перестаёт принимать управление от текущей регистрации;
- рабочий Xray и уже развёрнутый профиль на Node сохраняются;
- карточка остаётся в Cluster;
- для восстановления создаётся новая команда подключения.

### «Удалить» карточку Node

- карточка и связи удаляются из Cluster;
- SG-Panel больше не управляет сервером;
- Xray, Nginx и рабочая конфигурация на Node автоматически не уничтожаются.

### «Удалить только SG-Node Agent с сервера»

Команда находится в раскрывающемся блоке **«События и обслуживание»**. Она удаляет агентскую часть с Node. Перед запуском убедитесь, что понимаете, что рабочие сервисы и конфигурация могут потребовать отдельного обслуживания.

## Обновление компонентов SG-Node

В карточке Node раскройте **«События и обслуживание»** и скопируйте команду **«Обновить все компоненты SG-Node»**.

Повторный запуск полного установщика обновляет зависимости, Agent, Worker, Xray и Nginx, сохраняя регистрацию и рабочий профиль. После обновления проверьте heartbeat и состояние Xray.

## Типовые ошибки

### После установки нет `ready_to_connect`

Проверьте:

```bash
sudo tail -n 200 /var/log/sg-node-full-install.log
sudo cat /etc/sg-node/install.env
```

Не создавайте карточку до успешного завершения полной установки.

### Команда подключения сообщает, что Node не подготовлена

Сначала выполните именно команду **«Скопировать команду полной установки SG-Node»** из шага 1. Команда с токеном не заменяет полную установку.

### Токен истёк или уже использован

На карточке Node нажмите **«Создать новую команду»** либо **«Создать команду переподключения»**, затем запустите новую строку на Node.

### Agent и Worker работают, но шаг 5 закрыт

Обновите карточку через несколько секунд. Должны быть подтверждены heartbeat и версия Xray. Если статус не меняется, проверьте:

```bash
sudo systemctl status sg-node-agent --no-pager
sudo systemctl status sg-node-worker --no-pager
sudo journalctl -u sg-node-agent -n 100 --no-pager
sudo journalctl -u sg-node-worker -n 100 --no-pager
```

### Публичный адрес не определён

Введите реальный публичный IPv4 или домен в поле **«Публичный IP или домен»** карточки и нажмите **«Сохранить карточку»**. Не используйте Reality SNI как адрес Node.

### Профиль развёрнут, но клиент не подключается

Проверьте:

- `64441/tcp` в Security Group и firewall;
- публичный адрес в ссылке;
- состояние Xray;
- итоговый журнал задания;
- отсутствие другого процесса на порту;
- совпадение Flow и fingerprint в клиентской ссылке.

Команды на Node:

```bash
sudo systemctl status xray --no-pager
sudo journalctl -u xray -n 100 --no-pager
sudo ss -lntp | grep 64441
```

## Безопасность

- Enrollment token действует 30 минут и используется один раз.
- Постоянный Agent token хранится на Controller только в виде SHA-256.
- Подключение SG-Node к Controller является исходящим со стороны Node.
- Agent работает без `root`; привилегированные задания выполняет ограниченный Worker.
- Успешное подключение показывается только после принятого heartbeat.
- Применение конфигурации использует validate-first, backup и rollback.
- При временной недоступности Controller уже развёрнутый клиентский трафик продолжает работать.
- Не публикуйте команды подключения, Agent token и содержимое `agent.json`.


## Текущая граница RC70

Автоматическое первое развёртывание на удалённой Node ограничено VLESS REALITY RAW/TCP. XHTTP-TLS, Hysteria 2, Multi-Inbound, распределение GeoFiles, балансировка и failover должны добавляться отдельными проверяемыми этапами.
