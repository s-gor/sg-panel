# Установка SG-Panel

## Требования

- Ubuntu Server 24.04 LTS;
- архитектура `amd64`;
- отдельный сервер, VPS или EC2;
- root или sudo;
- минимум 1 ГиБ RAM;
- TCP `22` для SSH;
- TCP `443` для VLESS-профилей;
- отдельный TCP-порт панели, по умолчанию `61443`.

Для первой установки с `VLESS REALITY` домен и сертификат не нужны.

## Security Group или firewall

Минимальный набор для первого запуска:

| Порт | Источник |
|---:|---|
| `22/tcp` | ваш административный IP |
| `443/tcp` | адреса клиентов или необходимый диапазон |
| `61443/tcp` | ваш административный IP |

Дополнительно:

- `80/tcp` — для Let's Encrypt и публичной SG-заглушки;
- `443/udp` — для основного Hysteria 2;
- `8443/udp` и `9443/udp` — только если включены дополнительные Hysteria 2 Inbound;
- UDP-диапазон — только если включён Hysteria port hopping.

Не открывайте наружу `8080/tcp` и внутренние локальные порты Nginx.

## Проверка точного RC70 до публикации

Загрузите один файл в любой удобный каталог пользователя:

```text
070-INSTALL-SG-PANEL-RC70.run
```

Запустите:

```bash
sudo bash ./070-INSTALL-SG-PANEL-RC70.run
```

Это самодостаточный мастер чистой установки со встроенным точным комплектом RC70. До его запуска не требуется:

- выполнять `apt update`;
- устанавливать `curl`, `unzip`, Python, Nginx или Certbot;
- загружать или распаковывать отдельный ZIP;
- запускать отдельный updater.

Мастер сам извлекает встроенный комплект во временный каталог и с первой секунды показывает зелёную вертушку `| / - \`. Затем он без участия пользователя подготавливает Ubuntu, обновляет систему и устанавливает все системные зависимости. Только после успешного bootstrap появляются вопросы с параметрами панели.

## Установка после публикации в GitHub

```bash
curl -fsSL https://raw.githubusercontent.com/s-gor/sg-panel/main/install-from-github.sh -o /tmp/install-sg-panel.sh
sudo bash /tmp/install-sg-panel.sh
```

Bootstrap загружает единый `install.sh`, проверяет его синтаксис и передаёт управление тому же мастеру, который используется для локального ZIP.

Не используйте `curl | bash`: установщику нужен интерактивный терминал для первоначальных вопросов.

## Сначала подготовка системы, затем параметры панели

До первого вопроса мастер выполняет под зелёной вертушкой:

1. ожидание завершения cloud-init и освобождения apt/dpkg;
2. обновление Ubuntu;
3. установку `curl`, `ca-certificates`, `unzip`, `rsync`, Python, SQLite, Nginx, Certbot, OpenSSL и остальных обязательных компонентов;
4. определение публичного IPv4.

После этого мастер один раз спрашивает:

1. пароль администратора панели;
2. повтор пароля;
3. публичный HTTP-порт панели;
4. публичный IP или домен Xray;
5. имя этого сервера в панели;
6. имя первого клиента;
7. Reality target;
8. Reality SNI.

Имя сервера постоянно отображается в шапке и на странице входа. Позже его можно изменить в `System → Status & Services`, не меняя адрес, клиентов или Xray-конфигурацию.

После строки:

```text
[SG-Panel] Все параметры приняты. Установка продолжается без дополнительного ввода.
```

установщик больше ничего не спрашивает.

Когда показывается рекомендуемое значение, например:

```text
Порт панели [61443]:
```

для его принятия просто нажмите **Enter**.

## Живой прогресс без технического шума

С первой секунды и до завершения видны только семь аккуратных этапов:

```text
[SG-Panel] [|] Этап 1/7 · Подготовка чистой Ubuntu (0 сек)
[SG-Panel] [OK] Этап 1/7 · Подготовка чистой Ubuntu (2 сек)
[SG-Panel] [/] Этап 2/7 · Обновление Ubuntu (3 сек)
```

Полный порядок:

1. подготовка чистой Ubuntu и ожидание cloud-init/apt;
2. обновление Ubuntu;
3. установка системных компонентов;
4. определение публичного адреса;
5. проверка и распаковка SG-Panel RC70;
6. установка SG-Panel, Xray и Nginx;
7. финальная проверка панели и служб.

Между этапами 4 и 5 вертушка останавливается только на время интерактивного ввода параметров панели, после чего установка автоматически продолжается.

Вывод `apt`, `dpkg`, `curl`, `pip`, Xray, Nginx и `systemctl` уходит в журналы:

```text
/var/log/sg-panel-installer-*.log
/var/log/sg-panel-core-install-*.log
/var/log/sg-panel-install-*.log  # при прямом запуске внутреннего мастера
```

При ошибке мастер показывает:

- название неуспешного этапа;
- последние полезные строки;
- путь к полному журналу.

## Что создаётся при чистой установке

Мастер:

- ждёт завершения cloud-init и освобождения блокировок apt;
- при малом объёме RAM создаёт swap;
- обновляет Ubuntu;
- устанавливает системные зависимости;
- устанавливает или проверяет Xray `v26.5.9`;
- устанавливает SG-Panel `v0.10.0-rc70`;
- создаёт SQLite и первого клиента;
- создаёт VLESS REALITY RAW/TCP на `443/tcp`;
- включает XTLS Vision;
- использует fingerprint Firefox для нового профиля;
- настраивает Nginx и публичный HTTP-порт панели;
- запускает и проверяет службы.

## Ожидаемый результат

После завершения мастер показывает:

- адрес панели;
- адрес Xray;
- состояние SG-Panel, Xray и Nginx;
- необходимые правила Security Group;
- путь к первой клиентской ссылке;
- пути к журналам.

Откройте, например:

```text
http://SERVER_IP:61443
```

Первая клиентская ссылка:

```bash
sudo cat /root/sg-panel-first-user.txt
```

## Быстрая проверка

```bash
cd /opt/xpanel-mvp

.venv/bin/python -m xpanel --version
systemctl is-active xpanel-web
systemctl is-active xray
systemctl is-active nginx
systemctl is-active xpanel-traffic.timer
curl -fsS http://127.0.0.1:8080/login >/dev/null
sudo /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
```

Ожидается версия `0.10.0-rc70`, состояние `active` и успешная проверка `config.json`.

## Если установка прервалась

Повторно запустите ту же команду с тем же архивом:

```bash
sudo bash ./070-INSTALL-SG-PANEL-RC70.run
```

Внутренний мастер различает завершённую и частичную установку. Технические журналы не удаляются автоматически.

На чистом сервере нет предыдущей версии, к которой можно вернуться. Поэтому при ошибке первая установка безопасно останавливается и остаётся повторяемой. При обновлении уже работающей панели сначала создаётся резервная копия, а при ошибке запускается отдельный этап:

```text
Rollback · восстановление предыдущего рабочего состояния
```

Он также показывается с зелёной вертушкой и возвращает приложение, SQLite, Xray config, WARP, доступ панели и systemd-файлы.

## Включение HTTPS

HTTPS не включается автоматически при первой установке.

1. направьте DNS-запись `A` на сервер;
2. откройте TCP `80` и порт панели;
3. откройте `Security → Panel Access`;
4. выберите `HTTPS + Let's Encrypt`;
5. укажите домен и сохраните.

Подробнее: [HTTPS и fallback](HTTPS.md).

## Обновление

Основной способ находится в `Maintenance → Updates`:

1. откройте вкладку `Updates`;
2. нажмите **«Проверить сейчас»**;
3. проверьте установленную и найденную версии;
4. нажмите **«Обновить до …»**;
5. следите за живым журналом до состояния **«Готово»** или **«Восстановлено»**;
6. после завершения обновите страницу и проверьте клиентское подключение.

Ручной способ из распакованного каталога новой версии:

```bash
sudo bash install-or-upgrade.sh
```

Он сохраняет существующие настройки, пользователей, UUID, ключи, сертификаты, WARP, Routing, GeoFiles и режим доступа к панели. Перед копированием создаётся резервная копия. Технический вывод скрыт в журнале, а на экране остаются этапы, вертушка, время и итоговый статус.
