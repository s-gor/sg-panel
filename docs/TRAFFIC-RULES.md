# Traffic Rules

Traffic Rules определяют, какой Outbound получит соединение.

## Default Outbound

Используется, если ни одно правило не совпало.

```text
direct    интернет через IP текущего сервера
warp      интернет через Cloudflare WARP
TAG       пользовательский Outbound
```

Создание WARP или пользовательского Outbound само по себе не меняет Default Outbound.

## Порядок правил

Xray проверяет правила по приоритету и использует первое совпавшее.

Пример:

```text
10  Блокировать BitTorrent
20  Блокировать рекламу
30  Локальные сети напрямую
40  Франция через eu-exit
```

Ставьте более узкие исключения выше общих правил.

## Условия одного правила

Значения внутри одного поля работают как варианты. Разные поля должны совпасть одновременно.

```text
Domain:   domain:example.com
Port:     443
Network:  tcp
```

Такое правило применяется только к TCP `443` для указанного домена.

## Домены

Поддерживаемые формы Xray:

```text
domain:example.com
full:api.example.com
keyword:example
geosite:category-ads-all
geosite:fr
```

## IP и сети

```text
1.1.1.1
203.0.113.0/24
geoip:private
geoip:fr
```

Доменные и IP-условия страны обычно создаются отдельными правилами: `geosite:fr` и `geoip:fr`.

## Готовые шаблоны

Панель предлагает шаблоны для:

- рекламы;
- локальных сетей;
- страны;
- произвольной категории geosite.

После добавления проверьте порядок и цель правила.

## Sniffing

Рекомендуемая базовая схема:

```text
Sniffing:    включён
Route only:  включён
HTTP:        включён
TLS:         включён
QUIC:        включён
```

`Route only` использует найденный домен только для маршрутизации и не подменяет исходный адрес назначения.

## Domain strategy

- `AsIs` — использовать домен как есть;
- `IPIfNonMatch` — разрешить домен в IP, если доменные правила не совпали;
- `IPOnDemand` — выполнять разрешение при необходимости IP-условий.

Начинайте с `AsIs`. Для правил `geoip`, которые должны применяться к доменным запросам, может потребоваться `IPIfNonMatch`.

## WARP

Режимы WARP:

- выключен;
- только выбранные сайты;
- весь трафик.

При режиме всего трафика `warp` становится Default Outbound. Для выборочного режима добавляются обычные Traffic Rules с целью `warp`.

## Пользовательский Outbound

Создайте его в `Routing → Outbounds`, проверьте соединение, затем укажите tag в правиле или Default Outbound.

## Block

Блокирующее правило направляет совпавший трафик в системный `block`/blackhole Outbound. Перед широким правилом проверьте его на одном домене или клиенте.

## Balancers

Продвинутые balancer-настройки доступны через полный Routing JSON. Обычный интерфейс работает с `outboundTag`.

## Геоданные

Для `geoip:` и `geosite:` нужны активные `geoip.dat` и `geosite.dat`, содержащие именно указанные категории. В `Routing → GeoFiles` панель показывает реальные категории выбранной пары и отдельно проверяет её структурную исправность и совместимость с текущими правилами. Наличие `category-ads-all` не обязательно: используйте только категории, которые присутствуют в активном `geosite.dat`.

## Проверка

После применения:

1. откройте `System → Logs & Diagnostics`;
2. убедитесь, что `config.json` имеет состояние OK;
3. проверьте нужный сайт с реального клиента;
4. сравните внешний IP или ожидаемую блокировку;
5. проверьте, что соседний трафик не попал под правило случайно.
