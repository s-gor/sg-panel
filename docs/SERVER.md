# Xray Server и Inbound-профили

В текущем интерфейсе доступны **пять** Inbound-профилей:

1. `VLESS REALITY`;
2. `VLESS XHTTP-TLS`;
3. `VLESS XHTTP-REALITY`;
4. `Hysteria 2`;
5. `XHTTP-TLS + Hysteria 2`.

## Общий порядок переключения

1. Откройте `Xray Server → Inbound`.
2. Выберите профиль.
3. Заполните только параметры выбранного профиля.
4. Нажмите **«Проверить конфигурацию»**.
5. Убедитесь, что модель SG-Panel и `xray run -test` прошли успешно.
6. Нажмите **«Сохранить и применить»**.
7. Получите новую клиентскую ссылку или обновите подписку.
8. Проверьте подключение реального клиента.

Карточка **«Активен сейчас»** показывает работающий профиль. **«Выбрано для настройки»** — только черновик до успешного применения.

## VLESS REALITY

Базовый профиль новой установки.

Требует:

- публичный IP или hostname;
- Reality target, например `www.bing.com:443`;
- Reality SNI;
- private/public key;
- short ID;
- fingerprint;
- flow `xtls-rprx-vision`.

Собственный домен и сертификат не требуются.

После настройки собственного HTTPS-домена SG-Panel может использовать SNI-routing: клиентский Reality-трафик остаётся на публичном `443`, а обычный HTTPS-запрос к домену попадает на локальную Nginx-заглушку.

Reality target при этом не заменяется локальным адресом.

## VLESS XHTTP-REALITY

Использует VLESS, XHTTP и REALITY без сертификата Xray.

Ключевые параметры:

- Reality target и SNI;
- XHTTP host и path;
- XHTTP mode;
- fingerprint;
- short ID.

Доступны четыре режима:

- `auto` — значение по умолчанию;
- `packet-up`;
- `stream-up`;
- `stream-one`.

SG-Panel сохраняет выбранный mode в серверной конфигурации и в прямой клиентской ссылке. После смены mode получите новую ссылку или обновите подписку. Клиент и сервер должны использовать совместимые параметры.

При включённом fallback обычный HTTPS по собственному домену уходит на локальный Nginx, а клиентский Reality/XHTTP-трафик — в Xray.

## VLESS XHTTP-TLS

Требует:

- собственного домена;
- действующего сертификата Let's Encrypt;
- одного из четырёх XHTTP modes;
- уникального Path и loopback TCP-порта для каждого включённого экземпляра.

В RC39 можно одновременно включить до трёх XHTTP Inbound:

1. основной — сохраняет прежние Path и локальный порт, обычно `127.0.0.1:8443`;
2. резервный — отдельный стабильный Path и обычно `127.0.0.1:8444`;
3. дополнительный — отдельный стабильный Path и обычно `127.0.0.1:8445`.

Nginx принимает TLS на одном публичном `443/tcp` и по Path направляет запрос в нужный локальный listener Xray. Локальные порты `8443`–`8445` наружу не открываются. Обычный запрос вне клиентских Path показывает локальную SG-заглушку.

Один выбранный XHTTP mode используется всеми включёнными экземплярами. На реальном сервере ранее подтверждена работа `VLESS XHTTP-TLS` с каждым режимом:

- `auto`;
- `packet-up`;
- `stream-up`;
- `stream-one`.

После изменения Path или mode получите новые прямые ссылки или обновите подписку. Одинаковые Path, локальные `listen:port` и публичный listen для локального Xray блокируются.

В RC40 появился отдельный профиль `XHTTP-TLS + Hysteria 2`. Он одновременно добавляет в один `config.json` все включённые XHTTP Inbound и все включённые Hysteria 2 Inbound. XHTTP использует локальные TCP-listener за Nginx, а Hysteria 2 — публичные UDP-listener, поэтому `127.0.0.1:8443/tcp` и `0.0.0.0:8443/udp` не конфликтуют.


## XHTTP-TLS + Hysteria 2

Смешанный профиль предназначен для одновременной работы обеих транспортных семей:

- до трёх XHTTP Inbound через один публичный `443/tcp` и разные Path;
- до трёх Hysteria 2 Inbound на отдельных UDP-портах;
- общий домен и TLS-сертификат;
- отдельные tags, ссылки и QR-коды;
- одна подписка со всеми включёнными ссылками.

Nginx обслуживает только TCP-часть XHTTP. Hysteria 2 принимает UDP непосредственно в Xray. Для второго и третьего Hysteria Inbound по-прежнему нужно открыть соответствующие UDP-порты в Security Group. Основной Hysteria auth, дополнительные auth, XHTTP Path и UUID пользователей при переходе на смешанный профиль не пересоздаются.

## XMUX

XMUX является частью XHTTP и управляет параллелизмом, количеством и переиспользованием HTTP/2/HTTP/3-соединений. Его не следует путать со старым общим механизмом `mux.cool`.

В текущей версии SG-Panel отдельного интерфейса ручной настройки XMUX нет. Панель использует штатные значения Xray по умолчанию и не предлагает редактировать:

- `maxConcurrency`;
- `maxConnections`;
- `cMaxReuseTimes`;
- `hMaxRequestTimes`;
- `hMaxReusableSecs`;
- `hKeepAlivePeriod`.

Если эти параметры понадобятся позже, для них следует добавить отдельный экспертный блок с проверкой совместимости, а не подмешивать их незаметно в обычную форму.

## Внутренняя совместимость с gRPC + TLS

`gRPC + TLS` не является доступным пользовательским профилем текущей версии и не показывается среди карточек Inbound.

Часть backend-логики и тестов сохранена для внутренней совместимости. Это позволяет при необходимости вернуть профиль в будущей версии без повторного создания всей основы. Пока режим скрыт, его не следует считать шестой поддерживаемой схемой и не следует настраивать вручную через обычный интерфейс.

## Hysteria 2

Нативный профиль Xray поверх QUIC/UDP.

Требует:

- домена;
- сертификата;
- одного или нескольких открытых UDP-портов; основной по умолчанию `443`;
- клиента с поддержкой Hysteria 2.

TCP и UDP используют разные сокеты. Поэтому Hysteria может слушать `443/udp`, а Nginx одновременно показывать заглушку на `443/tcp`.

### Несколько Hysteria 2 Inbound

RC37 позволяет одновременно включить до трёх Hysteria 2 Inbound:

1. основной — использует публичный порт из общих настроек и сохраняет прежний UUID клиента как auth;
2. резервный — по умолчанию `8443/udp`;
3. дополнительный — по умолчанию `9443/udp`.

Для второго и третьего Inbound задаются отдельные название, listen и UDP-порт. SG-Panel создаёт уникальный tag и отдельный стабильный auth каждому клиенту. На странице клиента появляются отдельные ссылка и QR-код, а постоянная подписка включает все активные ссылки.

Общими для трёх экземпляров остаются домен, TLS-сертификат, masquerade, congestion control и остальные QUIC-параметры Hysteria Studio. Одинаковые UDP-порты применить нельзя. Дополнительные порты необходимо разрешить в Security Group и firewall именно по UDP.

### Hysteria Studio

Studio показывает:

- активность профиля;
- публичную UDP-точку;
- TLS и версию Xray;
- локальную готовность;
- результаты ручной проверки;
- QUIC и congestion-параметры;
- port hopping;
- masquerade.

### Presets и bandwidth

Начинайте с автоматического или стандартного профиля. Ручные ограничения Upload/Download задавайте только при известной пропускной способности сервера и клиента.

Неверные значения могут снизить скорость сильнее, чем отсутствие лимита.

### Port hopping

Укажите UDP-порты или диапазоны и откройте те же порты в Security Group/firewall. Не открывайте большой диапазон без необходимости. В RC37 port hopping разрешён только при одном активном Hysteria 2 Inbound, потому что его параметры являются общими для Hysteria Studio.

### Masquerade

Поддерживаемый тип masquerade выбирается в Studio. Перед применением используйте ручную проверку. Masquerade Hysteria не заменяет обычную HTTPS-заглушку Nginx на TCP `443`.

## Что сохраняется при переключении

SG-Panel сохраняет:

- клиентов;
- UUID/Auth;
- комментарии и сроки;
- токены подписок;
- накопленную статистику;
- Routing-настройки.

Меняются рабочий Inbound, формат прямой ссылки и содержимое подписки.

## Xray Config

Вкладка содержит:

- Current JSON — полный редактируемый документ SG-Panel;
- Generated Config — фактически сформированный `/usr/local/etc/xray/config.json`;
- проверку и применение;
- runtime-параметры и состояние.

Generated Config предназначен для просмотра. Ручное редактирование файла на диске будет потеряно при следующем применении из панели.

## Откат при ошибке

Перед применением SG-Panel создаёт резервную копию. Если новый config не проходит тест, Xray не запускается или локальная проверка профиля завершается ошибкой, панель возвращает прежнее состояние.

## Multi-REALITY в RC41

Профиль `VLESS REALITY` поддерживает до трёх одновременных TCP Inbound. Основной экземпляр сохраняет прежние порт и Short ID, а второй и третий получают собственные стабильные Short ID. Один общий Flow применяется ко всем включённым экземплярам: без Vision или `xtls-rprx-vision`. Этот профиль не смешивается с Hysteria 2.
