# HTTPS, домен и fallback

В SG-Panel есть три разных понятия, которые важно не смешивать:

1. HTTPS самой веб-панели;
2. TLS для `XHTTP + TLS` и Hysteria 2;
3. fallback обычного браузерного HTTPS на локальный Nginx.

## HTTPS панели

Панель работает на отдельном порту, например `61443`:

```text
https://panel.example.com:61443
```

Backend остаётся на `127.0.0.1:8080`. Nginx принимает публичное соединение.

### Включение

1. Создайте DNS-запись `A` на публичный IPv4.
2. Дождитесь обновления DNS.
3. Откройте TCP `80` и порт панели.
4. Откройте `Security → Panel Access`.
5. Выберите `HTTPS + Let's Encrypt`.
6. Укажите домен и порт.
7. Нажмите **«Сохранить и применить»**.
8. Дождитесь успешного завершения всех этапов.

Домен вводится без схемы и порта:

```text
panel.example.com
```

### Возврат на HTTP

В том же разделе выберите HTTP и укажите IP/hostname и порт. Сертификат при этом не обязательно удаляется.

## Сертификат Inbound-профилей

TLS-профили используют сертификат домена. Панель проверяет наличие файлов и срок действия.

Hysteria 2 получает отдельную runtime-копию закрытого ключа с ограниченными правами для Xray.

## SG-заглушка на порту 80

После установки Nginx публикует локальную страницу SG на TCP `80`. Она также используется для HTTP-01 Let's Encrypt.

Эта страница не является панелью и не содержит административных функций.

## Обычный HTTPS на TCP 443

### RAW/TCP + REALITY и XHTTP + REALITY

При настроенном домене Nginx stream читает SNI без расшифровки:

- клиентский Reality SNI направляется в Xray;
- обычный SNI собственного домена направляется на локальную HTTPS-заглушку.

Публичный адрес клиента остаётся `DOMAIN_OR_IP:443`.

### XHTTP + TLS

Nginx сам принимает TLS на `443/tcp`:

- клиентский XHTTP path передаётся в Xray на `127.0.0.1:8443`;
- все остальные запросы получают локальную заглушку.

### Hysteria 2

Xray слушает `443/udp`, а Nginx одновременно может слушать `443/tcp`. Поэтому браузер видит заглушку, а Hysteria-клиент использует UDP.

## Проверка

Проверка панели:

```bash
curl -I https://panel.example.com:61443
```

Проверка обычной заглушки:

```bash
curl -I https://panel.example.com/
```

Проверка сертификата:

```bash
openssl s_client -connect panel.example.com:443 -servername panel.example.com </dev/null
```

Проверка Xray:

```bash
sudo /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
```

## Типичные ошибки

### Сертификат не выпускается

Проверьте DNS, TCP `80`, отсутствие второго веб-сервера и журнал операции в панели.

### Панель открывается по старому адресу

Используйте итоговый URL, показанный после переключения. Браузер может сохранить старый адрес или блокировать автоматический переход на другой порт.

### Reality перестал подключаться после включения домена

Проверьте, что Reality SNI не совпадает с доменом локальной заглушки, и что клиент использует актуальную ссылку.

### На 443 нет заглушки

Проверьте Nginx, сертификат, stream-модуль и активный Inbound-профиль в Diagnostics.
