# Cloudflare WARP

SG-Panel создаёт WARP как встроенный WireGuard Outbound Xray с тегом:

```text
warp
```

Системный `warp-cli`, отдельный `wg-quick@warp` и изменение маршрута Ubuntu не требуются. WireGuard работает внутри Xray.

## Где настраивается

| Задача | Раздел |
|---|---|
| создать, проверить, включить, пересоздать или удалить WARP | `Routing → Outbounds` |
| выбрать, какой трафик идёт через WARP | `Routing → Traffic Rules` |
| проверить endpoint, Default Outbound и журналы | `System → Logs & Diagnostics` |

## Путь трафика

```text
Клиент → активный Inbound → Xray → Traffic Rules → warp → Cloudflare → Интернет
```

WARP не меняет Inbound и может использоваться с любым из четырёх доступных входящих профилей.

## Создание

1. Откройте `Routing → Outbounds`.
2. Нажмите **«Создать WARP»**.
3. Дождитесь регистрации профиля.
4. Выполните обязательную проверку.
5. Только после успешной проверки сохраните и примените изменение.

SG-Panel:

- регистрирует профиль через `wgcf-cli`;
- создаёт WireGuard Outbound Xray;
- использует IPv4 endpoint `162.159.192.1:2408`;
- помещает ключи и Outbound во временную копию SQLite;
- формирует кандидат `config.json`;
- выполняет `xray run -test`;
- записывает рабочие данные только после успешной проверки.

Создание WARP само по себе ещё не направляет через него пользовательский трафик.

## Проверка WARP

Нажмите **«Проверить WARP»** до изменения Default Outbound.

Панель временно запускает отдельный локальный SOCKS-вход Xray и выполняет запрос через WARP. Рабочий Inbound не останавливается.

Ожидаемый результат:

```text
WARP on, IP ...
```

или:

```text
WARP plus, IP ...
```

IPv6 в результате может быть нормальным выходным адресом Cloudflare.

## Режимы Traffic Rules

### Не использовать WARP

WARP остаётся настроенным, но не выбирается правилами и не является Default Outbound.

### Только выбранные сайты

В карточке **WARP Routing** условия разделены на два поля:

- **Домены / Geosite** — `domain:`, `full:`, `keyword:`, `regexp:`, `geosite:`;
- **IP / GeoIP / CIDR** — `geoip:`, отдельный IP или сеть CIDR.

Пример:

```text
Домены / Geosite
geosite:category-ru

IP / GeoIP / CIDR
geoip:ru
```

SG-Panel создаёт два отдельных управляемых правила WARP. Это не дублирование: Xray объединяет разные поля внутри одного правила логическим AND. Раздельные правила позволяют совпасть либо домену, либо IP-адресу.

Остальной трафик продолжит использовать Default Outbound.

### Готовые российские пресеты

1. Создайте и включите WARP Outbound.
2. Откройте `Routing → Traffic Rules`.
3. Выберите один из двух вариантов.

**Только российские доменные зоны:**

```text
geosite:tld-ru
```

Этот список включает `.ru`, `.su`, `.moscow`, `.tatar` и русскоязычные IDN-зоны из активного `geosite.dat`.

**Российские сайты и IP:**

```text
geosite:category-ru
geoip:ru
```

`category-ru` уже включает `tld-ru`, поэтому добавлять оба значения одновременно не нужно. Панель также не создаёт regexp для `.ru`, `.su`, `ru.com` или `ru.net`.

4. Панель выберет режим **«Только выбранные сайты»** и заполнит соответствующие поля.
5. Нажмите **«Проверить конфигурацию»**.
6. После успешной проверки сохраните и примените изменение.

Если активные GeoFiles не содержат `category-ru` или `ru`, это не обязательно означает повреждение файлов. Панель не изменит рабочий Xray, покажет отсутствующие категории и предложит выбрать совместимый комплект в `Routing → GeoFiles` либо изменить условия WARP.

### Весь трафик через WARP

`warp` становится Default Outbound. Отдельная строка WARP в таблице правил может отсутствовать — это нормально.

Более ранние явные правила, например блокировка, продолжают выполняться до маршрута по умолчанию.

## Подтверждённый сценарий: Hysteria 2 через WARP

Этот сценарий проверен на рабочем сервере:

```text
Клиент → Hysteria 2 → Xray → WARP → Интернет
```

Hysteria 2 остаётся входящим подключением, а WARP становится выходом Xray. Перенастраивать Hysteria-клиент не требуется:

- ссылка `hysteria2://` не меняется;
- UDP-порт и port hopping не меняются;
- персональный Auth клиента не меняется;
- TLS, SNI и masquerade не меняются.

Порядок включения:

1. Убедитесь, что клиент уже подключается через `Hysteria 2` без WARP.
2. Откройте `Routing → Outbounds`.
3. Создайте WARP, если он ещё не создан.
4. Нажмите **«Проверить WARP»** и дождитесь результата `WARP on` или `WARP plus`.
5. Откройте `Routing → Traffic Rules`.
6. Выберите режим **«Весь трафик через WARP»**.
7. Выполните обязательную проверку конфигурации.
8. Нажмите **«Сохранить и применить»**.
9. Переподключите Hysteria-клиент и проверьте внешний IP.

В верхней сводке `Routing → Traffic Rules` после применения должны отображаться:

```text
Default Outbound: WARP
WARP mode: ALL
```

Внешний IP клиента при этом не должен совпадать с публичным IP сервера EC2.

### Быстрый возврат на обычный выход

Если после включения WARP сайты перестали открываться:

1. откройте `Routing → Traffic Rules`;
2. выберите режим **«Не использовать WARP»**;
3. проверьте и примените конфигурацию;
4. переподключите клиент.

Default Outbound вернётся на `direct`. Hysteria-ссылка, UDP-порт и Auth клиента останутся прежними.

## Подробная проверка выборочной маршрутизации

### 1. Убедиться, что правила созданы

После применения пресета в таблице `Правила маршрутизации` должны быть две включённые строки:

```text
40  Cloudflare WARP       domain geosite:category-ru  → warp
41  Cloudflare WARP — IP  ip geoip:ru                 → warp
```

Меньшее значение приоритета выполняется раньше. Защитные правила `10` и `20` должны остаться выше WARP.

### 2. Понять, почему обычный IP-checker показывает EC2

В режиме `Только выбранные сайты` через WARP проходит только совпавший трафик. Поэтому произвольный зарубежный сайт проверки IP может показать публичный IP EC2. Это ожидаемое поведение, а не признак неисправности WARP.

### 3. Создать временное контрольное правило

Нажмите `Добавить правило` и заполните:

| Поле | Значение |
|---|---|
| Название | `WARP test — ifconfig.me` |
| Приоритет | `39` |
| Выход | `warp` |
| Домены | `domain:ifconfig.me` |
| Сеть | `tcp,udp` |
| Остальные условия | оставить пустыми |

Сначала нажмите `Проверить конфигурацию`, затем `Создать правило`.

Переподключите клиент или откройте новую приватную вкладку и посетите `ifconfig.me`. Показанный адрес должен:

- отличаться от публичного IP EC2;
- соответствовать выходу Cloudflare, показанному кнопкой `Проверить WARP`;
- быть IPv4 или IPv6 — оба варианта допустимы.

После подтверждения удалите временное правило.

### 4. Проверить настоящий российский домен

Оставьте только управляемые правила `40` и `41` и откройте `2ip.ru`. В текущем комплекте GeoFiles он попадает под российское правило.

Ожидаемый результат:

- показан адрес Cloudflare/WARP, а не IP EC2;
- провайдер может определяться как Cloudflare;
- обычный зарубежный IP-checker продолжает показывать IP EC2, если для него нет отдельного правила.

### 5. Добавить конкретный сайт

Добавьте условие новой строкой в карточке WARP Routing:

```text
Домены / Geosite
geosite:category-ru
domain:example.ru
```

или:

```text
IP / GeoIP / CIDR
geoip:ru
203.0.113.0/24
```

Поддерживаются:

- `domain:` — домен и поддомены;
- `full:` — точное доменное имя;
- `keyword:` — часть доменного имени;
- `regexp:` — регулярное выражение;
- `geosite:` — категория `geosite.dat`;
- `geoip:` — категория `geoip.dat`;
- отдельный IP или CIDR.

Каждое условие вводится с новой строки, без запятых. После любого изменения снова выполните `Проверить конфигурацию` и `Сохранить и применить`.

## Проверка результата для режима всего трафика

1. примените конфигурацию;
2. переподключите клиент;
3. откройте любой сайт проверки IP;
4. убедитесь, что внешний IP не совпадает с публичным IP EC2;
5. проверьте, что в верхней сводке `Default Outbound` равен `WARP`.

## Отключение

Отключение:

- исключает `warp` из рабочего `config.json`;
- возвращает Default Outbound на `direct`, если это необходимо;
- отключает связанные правила;
- сохраняет учётные данные для последующего включения.

Операция проходит обязательную проверку перед сохранением и применением.

## Пересоздание

Пересоздание регистрирует новый профиль и заменяет WireGuard-ключи и адреса.

Новые данные сначала проверяются на временной базе. Прежний профиль не перезаписывается, если кандидат не проходит `xray run -test`.

После пересоздания повторите отдельную проверку WARP.

## Удаление

Удаление:

- удаляет Outbound `warp`;
- удаляет или отключает связанные правила;
- возвращает Default Outbound на `direct`, если требуется;
- удаляет сохранённые данные WARP.

Перед записью SG-Panel проверяет конфигурацию без WARP на временной SQLite-копии.

## Где хранятся данные

```text
/opt/xpanel-mvp/data/panel.db
/etc/xpanel-mvp/warp
```

Private key не показывается в обычном интерфейсе. Файлы WARP и резервные копии являются секретными.

## Типичные ошибки

### Проверка завершается timeout

Проверьте исходящий UDP и endpoint:

```text
162.159.192.1:2408
```

### После включения сайты не открываются

Верните Default Outbound на `direct`, примените конфигурацию и проверяйте WARP отдельно.

### Клиент показывает IP сервера

Проверьте:

- WARP включён;
- тест WARP успешен;
- выбран режим всего трафика или существует подходящее правило;
- более раннее правило не отправляет трафик в `direct`.

### Выборочные сайты не работают

Проверьте:

- `geosite:` находится в поле **Домены / Geosite**;
- `geoip:` находится в поле **IP / GeoIP / CIDR**;
- активные `geosite.dat` и `geoip.dat` содержат выбранные категории;
- в блоке **Фактически созданные правила** видны отдельные domain- и ip-правила;
- более раннее правило не отправляет трафик в `direct` или `blocked`;
- Sniffing, Route only и `domainStrategy` соответствуют вашей схеме.
