# Контракт SG-Panel → SG Client

## Формат

SG Client получает JSON по адресу подписки с параметром `format=json` и предпочитает объект `managedV2` со схемой `sg-panel-managed-profile-v2`.

Каждое соединение содержит URI и отдельную структурированную модель. URI сохраняется для совместимости, а managed v2 передаёт значения, которые невозможно безопасно или полностью представить обычной ссылкой.

## Серверно-управляемые поля

SG Client не должен разрешать обычному пользователю независимо включать или придумывать:

- тип безопасности и транспорт;
- Server Name;
- XTLS Flow;
- Reality public key и short ID;
- ECHConfig;
- verifyPeerCertByName;
- certificate SHA-256;
- пользовательскую CA PEM.

FinalMask допускает экспертный override, но только после локальной проверки Xray и с явным указанием, что серверная и клиентская части должны быть совместимы.

## REALITY

Для REALITY объект `tls.applicable` равен `false`. ECH, pinning и PEM отсутствуют. Flow берётся из профиля и не меняется локально.

## TLS

По умолчанию:

```json
{
  "mode": "system_ca",
  "systemCaEnabled": true,
  "disableSystemRoot": false
}
```

Дополнительные поля появляются только при реальной настройке SG-Panel. Источник каждого значения передаётся отдельно.

## Доверие

Контракт содержит `trustOnFirstUse: false`. Получение удалённого сертификата само по себе не является основанием автоматически закрепить его SHA-256.

## Секреты

`echServerKeys`, TLS private key и другие серверные секреты не экспортируются. Token подписки является секретом клиентского доступа.
