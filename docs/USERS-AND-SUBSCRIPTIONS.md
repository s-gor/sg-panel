# Пользователи, deployments и подписки

Документ относится к версии `v0.10.0-rc70`.

Клиент создаётся один раз в центральной базе Controller. Его имя, UUID/Auth, срок, комментарий и subscription token не зависят от конкретной Node. Присутствие клиента на сервере хранится отдельно как deployment.

## Что видно в обычном интерфейсе

В `Clients` и `Cluster` для подключения показываются только:

- сервер;
- профиль;
- фактическое состояние;
- включение в постоянную подписку.

По умолчанию Controller автоматически определяет порядок проверенных подключений. Технические роли, числовые приоритеты и ручное переключение не входят в обычный сценарий.

Ручной порядок доступен только в `Clients → карточка клиента → Серверы подключения → Эксперт · Управление подключениями`. Там можно выбрать автоматический режим либо вручную указать основное и резервное подключение и порядок переключения.

Если UUID клиента изменён, прежняя удалённая запись становится `error` и исключается из подписки до явного повторного развёртывания.

## Массовое развёртывание Node

В карточке SG-Node можно развернуть активную центральную базу клиентов одной операцией. Controller:

1. формирует одну совместимую конфигурацию;
2. сохраняет известных клиентов из последней подтверждённой конфигурации Node;
3. запускает проверку итогового Xray config;
4. создаёт страховочную копию;
5. применяет конфигурацию или выполняет rollback при ошибке.

После успешного задания подключения появляются в стабильных подписках, а их порядок Controller выбирает автоматически.

## Важное ограничение

Постоянная подписка меняет состав и порядок после следующего обновления клиентским приложением. Одиночная VLESS/Hysteria-ссылка, уже импортированная пользователем, дистанционно не переписывается. Для быстрого переноса используйте постоянную подписку и заранее разверните клиента на совместимом сервере.
