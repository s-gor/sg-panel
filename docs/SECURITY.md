# Security и Panel exposure

Раздел Security управляет HTTPS панели, способом публикации, паролем, сессиями, IP allowlist и публичными подписками.

## Архитектура

```text
Браузер → публичный Nginx → SG-Panel backend 127.0.0.1:8080
```

Backend напрямую наружу не публикуется. Panel exposure выбирает один из трёх маршрутов и показывает готовность, но не настраивает внешние сервисы автоматически.

## Direct through Nginx

```text
Браузер → Nginx на сервере → 127.0.0.1:8080
```

Используйте HTTPS, сложный пароль, IP allowlist и внешний firewall. Cloudflare hostname, Tunnel name и Cloudflare-подтверждения в этом режиме не нужны.

## Cloudflare Proxy

```text
Браузер → Cloudflare Proxy → Nginx → 127.0.0.1:8080
```

Поддерживаемые стандартным Cloudflare Proxy HTTPS-порты: `443`, `2053`, `2083`, `2087`, `2096`, `8443`. Порт `61443` не поддерживается.

Порядок перехода:

1. создать hostname и включить orange cloud;
2. перевести панель на поддерживаемый HTTPS-порт;
3. проверить вход через hostname;
4. разрешить origin-порт только сетям Cloudflare во внешнем firewall;
5. проверить вход повторно;
6. подтвердить origin lockdown в SG-Panel.

`CF-Connecting-IP` следует использовать только после закрытия прямого доступа к origin.

## Cloudflare Tunnel + Access

```text
Браузер → Cloudflare Access → Tunnel → локальный Nginx → 127.0.0.1:8080
```

`cloudflared` создаёт исходящее соединение. После проверки Tunnel и Access публичный входящий порт панели можно закрыть.

Порядок:

1. создать Tunnel и установить `cloudflared`;
2. связать hostname с локальным Nginx;
3. создать Access self-hosted application;
4. создать policy доступа;
5. проверить вход в приватном окне;
6. подтвердить Access в SG-Panel;
7. закрыть публичный порт во внешнем firewall.

## Значение подтверждений

- **Я уже ограничил origin во внешнем firewall** — только подтверждение выполненного правила AWS Security Group/firewall. Переключатель сам ничего не меняет.
- **Я уже создал Cloudflare Access application и policy** — только подтверждение созданных объектов Cloudflare. Переключатель сам их не создаёт.

SG-Panel также не создаёт DNS-записи, Tunnel и Access policy.

## Как не потерять доступ

Не закрывайте старый маршрут, пока новый не проверен в отдельном приватном окне. Убедитесь, что можете повторно войти и открыть Security. Только после этого ограничивайте origin или закрывайте публичный порт.

## Остальные настройки Security

После смены пароля все административные сессии завершаются. IP allowlist панели и allowlist подписок независимы. Перед включением строгого `/32` добавьте текущий адрес и сохраните резервный доступ через SSH-туннель.

```bash
ssh -L 61443:127.0.0.1:61443 ubuntu@SERVER_IP
```
