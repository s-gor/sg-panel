# Cascade в SG-Panel UI19

Cascade строит цепочку:

```text
Клиент → сервер подключения → сервер выхода → Интернет
```

Пользователь продолжает использовать обычную ссылку **сервера подключения**. Сайты видят публичный IP **сервера выхода**.

## Вариант 1: SG-Node из Cluster

Это основной сценарий для Controller и подключённой SG-Node.

1. На Controller откройте **Cascade**.
2. Выберите **SG-Node из Cluster**.
3. Нажмите карточку нужной ноды.
4. Нажмите **Включить Cascade**.

Дальше SG-Panel делает всё сама:

- создаёт на ноде только служебный доступ Cascade;
- сохраняет действующие профили, клиентов и Routing ноды;
- проверяет полный будущий Xray config;
- применяет его с резервной копией и rollback;
- проверяет фактический выходной IP;
- включает Cascade на Controller.

На странице появится сначала состояние автоматической настройки, затем маршрут со статусом **Работает**.

Не нужно заранее создавать обычный профиль, копировать QR или открывать Xray Server на ноде.

### Требование к подключённой ноде

На Controller и на полной SG-Panel, подключённой как Node, должна быть установлена одна cumulative-версия UI19. UI19 updater автоматически обновляет Node Worker до `0.7.0`, не отключая Nginx и не заменяя действующий Xray config.

## Вариант 2: две самостоятельные SG-Panel

Этот сценарий нужен, когда второй сервер не подключён в Cluster.

### На сервере, чей IP должны видеть сайты

1. Откройте **Cascade**.
2. Выберите **Другая SG-Panel**.
3. В карточке **Этот сервер должен быть выходом** нажмите **Создать ссылку**.
4. Нажмите **Скопировать ссылку**.

Профиль Xray Server вручную переключать не требуется.

### На сервере, к которому подключаются клиенты

1. Откройте **Cascade → Другая SG-Panel**.
2. Вставьте ссылку в карточку **К этому серверу подключаются клиенты**.
3. Нажмите **Подключить Cascade**.

Панель сразу импортирует ссылку, выполнит реальную проверку и включит маршрут. Отдельных кнопок `Проверить` и `Включить` в штатном сценарии нет.

## Где создавать клиентов

Обычные клиенты создаются только в **Clients** сервера подключения. Их ссылки и UUID при настройке Cascade не меняются.

## Как проверить

1. Подключитесь обычной ссылкой сервера подключения.
2. Откройте сайт проверки IP.
3. Он должен показать адрес сервера выхода, который указан в активном маршруте Cascade.

## Временно вернуть Direct

Нажмите **Вернуть Direct** в карточке активного маршрута. Параметры Cascade сохранятся, а обычные клиентские ссылки останутся прежними.

## Полностью удалить Cascade

Нажмите **Удалить Cascade**.

Для Cluster-сценария Controller поставит ноде безопасное задание, удаляющее только служебный UUID/служебный Inbound Cascade. Остальные профили и клиенты Xray сохраняются.

Для двух самостоятельных панелей удаление выполняется отдельно на каждой панели, где был создан соответствующий локальный компонент.

## Типовые сообщения

### Нода не в сети

Верните SG-Node в статус **В сети** и повторите одну кнопку. Ручное редактирование Xray не требуется.

### Требуется Worker UI19

Установите `SG-PANEL-FIX40-UI19.run` на самой полной SG-Panel/Node. Updater сохранит панель и перезапустит Agent/Worker.

### Настройка не завершена

Откройте **Cluster → нода → Дополнительно → Журнал и обслуживание**. Повторное создание обычных клиентов или профилей не требуется.

### Проверка маршрута не пройдена

Проверьте доступность публичного адреса/порта ноды и AWS Security Group. SG-Panel оставит прежний рабочий маршрут и покажет текст ошибки.

## Что UI19 не меняет

Cascade не должен самовольно менять:

- обычных клиентов и их UUID;
- действующие XHTTP/REALITY-профили;
- TLS-сертификаты;
- GeoFiles;
- пользовательские Routing rules;
- Nginx и доступ к веб-панели ноды.
