# Ежедневное использование SG-Panel

## Перед началом

Откройте **System → Resources**.

Нормальное состояние:

```text
Xray              active
Inbound           выбранный профиль
Default Outbound  direct, warp или пользовательский выход
Clients           активных / всего
```

Если верхний индикатор показывает **«Требуется проверка»**, откройте **System → Status & Services**, затем **Logs & Diagnostics**.

## Как применяется изменение

Для Clients, Inbound, Outbounds, Traffic Rules, DNS и WARP используется один безопасный цикл:

1. вы изменяете форму или Current JSON;
2. нажимаете **«Проверить конфигурацию»**;
3. SG-Panel создаёт временную копию SQLite;
4. применяет черновик только к временной копии;
5. собирает полный `config.json`;
6. выполняет `xray run -test`;
7. после успеха разблокирует **«Сохранить и применить»**;
8. создаёт резервную копию и применяет конфигурацию;
9. при ошибке возвращает предыдущий рабочий вариант.

Рабочая база и запущенный Xray не изменяются во время проверки. Любое изменение поля после успешной проверки снова блокирует сохранение. Автосохранения нет.

## Clients

Откройте **Clients → Clients**. Для каждого человека или устройства создавайте отдельного пользователя. Это позволяет независимо:

- отключать доступ;
- задавать срок действия;
- менять UUID;
- выдавать прямую ссылку;
- выдавать персональную подписку.

Полный список можно редактировать через **Users JSON** с тем же workflow проверки.

Подробно: [Пользователи, ссылки и подписки](USERS-AND-SUBSCRIPTIONS.md).

## Inbound

Откройте **Xray Server → Inbound**, выберите профиль, проверьте конфигурацию и сохраните.

После переключения:

- UUID пользователей сохраняются;
- Traffic Rules и Outbounds сохраняются;
- старая прямая ссылка может перестать работать;
- подписку нужно обновить в клиенте.

Подробно: [Основные Inbound-профили](INBOUND-PROFILES.md).

## Default Outbound и Traffic Rules

Default Outbound используется, когда ни одно правило не совпало.

```text
direct   интернет через IP сервера
warp     интернет через Cloudflare WARP
```

Выбор выполняется на странице **Network → Traffic Rules**, а создание выходов — на **Network → Outbounds**.

Правила выполняются сверху вниз. Меньший приоритет выполняется раньше:

```text
10  блокировка BitTorrent
20  блокировка рекламы
40  выборочный WARP
100 общее правило
```

Если заполнено несколько разных условий одного правила, они должны совпасть одновременно.

## WARP

Правильный порядок:

1. **Network → Outbounds** — создать WARP;
2. там же выполнить отдельную проверку WARP;
3. **Network → Traffic Rules** — выбрать режим;
4. **System → Resources** — проверить Default Outbound.

Не направляйте весь трафик через WARP, пока проверка не показывает `WARP on` или `WARP plus`.

Подробно: [Cloudflare WARP](WARP.md).

## DNS

Для обычного сервера внутренний DNS Xray можно оставить выключенным.

Откройте **Network → DNS**, когда требуются:

- отдельный DNS-сервер для выбранных доменов;
- специальные hosts;
- fallback;
- правила с `geoip`;
- расширенный DNS JSON.

## Current JSON и Generated Config

Во всех подходящих разделах Current JSON является равноправным экспертным инструментом.

Панель показывает кнопки:

```text
Форматировать
Проверить
Синхронизировать
Сохранить и применить
```

**Синхронизировать** заменяет несохранённый текст актуальным JSON из SQLite. **Generated Config** остаётся read-only и показывает фактически сформированный Xray config.

Полный редактор находится в **Xray Server → Xray Config**.

## Security

В правом верхнем углу доступны:

- текущая версия;
- состояние системы;
- Системная, Светлая и Тёмная темы;
- справка;
- меню администратора.

HTTP/HTTPS, пароль, сессии и IP allowlist находятся в **Security**.

## Backups

Откройте **Maintenance → Backups** перед:

- большим изменением Traffic Rules;
- редактированием полного JSON;
- сменой нескольких Outbounds;
- экспериментами с DNS.

После восстановления проверьте System, Inbound, Outbounds и Traffic Rules.
