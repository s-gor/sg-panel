# Руководство пользователя SG-Panel

Это руководство описывает функции версии `v0.10.0-rc45`.

## Первый вход

После установки откройте адрес, показанный мастером:

```text
http://PUBLIC_IP:ПОРТ_ПАНЕЛИ
```

После авторизации открывается `System → Resources`.

В верхней панели можно выбрать одну из двух тем:

- **Графит** — основная тема по умолчанию;
- **Светлая** — ручной светлый режим.

Системная тема в RC45 удалена. Выбор сохраняется в браузере. Подробности: [Темы SG-Panel](THEMES.md).

Отдельный раздел **Help** содержит встроенную русскую справку. Значки `?` возле сложных настроек открывают сразу нужный раздел.

Первую клиентскую ссылку можно получить двумя способами:

- открыть `Clients`, выбрать `sg-admin` и нажать **«Ссылка, QR и подписка»**;
- выполнить на сервере `sudo cat /root/sg-panel-first-user.txt`.

## Как SG-Panel применяет изменения

Формы и JSON-редакторы используют один порядок:

1. изменить параметры;
2. нажать **«Проверить конфигурацию»**;
3. дождаться успешной проверки модели и `xray run -test`;
4. нажать **«Сохранить и применить»**.

Проверка выполняется на временной копии SQLite. Рабочая база и запущенный Xray на этом этапе не меняются.

Если после проверки изменить поле, открыть старую вкладку или если другой администратор изменит конфигурацию, прежнее разрешение на сохранение становится недействительным.

## System

### Resources

Показывает:

- потребление памяти SG-Panel;
- доступную память сервера;
- Xray, Nginx, ядро, сеть и файловый кэш;
- CPU, диск, uptime и load average.

Linux использует свободную RAM как файловый кэш. Поэтому состояние памяти оценивается по `MemAvailable`, а не по сумме формально занятой памяти.

### Status & Services

Проверьте, что активны:

```text
xpanel-web
xray
nginx
xpanel-traffic.timer
```

### Logs & Diagnostics

Здесь собраны журналы SG-Panel, Xray, Nginx, портов и результат `xray run -test`. Большие журналы закрыты по умолчанию и открываются отдельно.

## Clients

Для каждого устройства создавайте отдельного клиента. Это позволяет независимо:

- отключить устройство;
- задать срок действия;
- пересоздать UUID/Auth;
- увидеть трафик и последнюю активность;
- сбросить статистику только одного клиента.

Обычный порядок:

1. нажать **«Новый клиент»**;
2. указать имя, комментарий и срок;
3. проверить конфигурацию;
4. сохранить и применить;
5. открыть ссылку, QR или подписку;
6. импортировать её в клиентское приложение.

## Xray Server

На вкладке `Inbound` выбирается основной профиль подключения.

Карточка **«Активен сейчас»** показывает реально работающий профиль. Карточка **«Выбрано для настройки»** означает только черновой выбор до проверки и применения.

Доступны пять профилей:

- `VLESS REALITY`;
- `VLESS XHTTP-REALITY`;
- `VLESS XHTTP-TLS`;
- `Hysteria 2`;
- `XHTTP-TLS + Hysteria 2`.

Для обоих XHTTP-профилей можно выбрать `auto`, `packet-up`, `stream-up` или `stream-one`. `auto` — значение по умолчанию, а не фиксированный режим. После изменения mode получите новую ссылку или обновите подписку.

При переключении профиля UUID/Auth клиентов сохраняются. На странице клиента старые ссылки остаются в разделе сохранённых неактивных, а подписка меняется и содержит только текущий активный набор.

Hysteria Studio содержит отдельную проверку TLS, UDP-порта, QUIC-параметров, port hopping и masquerade.

В RC37 можно одновременно включить до трёх Hysteria 2 Inbound. Основной сохраняет прежний порт и UUID/Auth, а резервный и дополнительный получают отдельные UDP-порты и стабильные auth. Для каждого формируются собственные ссылка и QR-код; подписка содержит весь активный набор. Port hopping совместим только с одним активным Hysteria 2 Inbound.

## Network

### Traffic Rules

Правила обрабатываются сверху вниз. Используется первое совпавшее правило.

`Default Outbound` применяется, если ни одно правило не совпало:

```text
direct   выход через IP сервера
warp     выход через Cloudflare WARP
TAG      выход через пользовательский Outbound
```

### Outbounds

Пользовательский Outbound — это клиентское VLESS-подключение текущего сервера к другому Xray-серверу. После создания Outbound добавьте Traffic Rule или выберите его как Default Outbound.

### DNS

Встроенный DNS Xray нужен, когда правила зависят от доменов, `geoip`, отдельных upstream или статических hosts-записей.

На обычном IPv4-сервере чаще всего используют `UseIPv4`.

### WARP

Доступны три режима:

- не использовать WARP;
- только выбранные сайты;
- весь трафик через WARP.

Создание WARP-профиля само по себе не меняет маршрутизацию. Выберите режим на странице Traffic Rules.

## Security

В разделе доступны:

- переключение HTTP/HTTPS;
- изменение домена и публичного порта панели;
- смена пароля;
- timeout сессии;
- IP allowlist;
- отдельные ограничения подписок;
- завершение активных сессий;
- журнал входов и действий администратора.

После смены пароля административные сессии завершаются.

Перед включением IP allowlist убедитесь, что текущий адрес или сеть присутствуют в списке. Loopback разрешается всегда.

## Maintenance

Вкладка `Backups` создаёт, проверяет и восстанавливает обычные копии SQLite и итоговой конфигурации. Перед крупным изменением создайте такую копию и скачайте её на локальный компьютер.

Вкладка `Updates` показывает установленную и последнюю опубликованную версии. Нажмите **«Проверить сейчас»**. Если более новая версия найдена, появится кнопка **«Обновить до …»**. Если установлена последняя версия, кнопка останется недоступной — это нормальный результат проверки.

После подтверждения обновление выполняется отдельной системной операцией с живым журналом: сначала проверяется кандидат, затем создаётся полная страховочная копия, устанавливаются файлы и проверяются SG-Panel, Xray, Nginx и таймеры. Кратковременная потеря связи с браузером во время перезапуска панели не останавливает операцию. При ошибке предыдущая рабочая версия восстанавливается автоматически.

Первый переход со старой версии без вкладки `Updates` выполняется обычной установочной командой или из проверенного ZIP. Подробности: [Maintenance, резервные копии и обновления](MAINTENANCE.md).

## Обычные сценарии

### Добавить клиента

`Clients → Новый клиент → Проверить конфигурацию → Сохранить и применить`.

### Выдать постоянную подписку

`Clients → выбрать клиента → Ссылка, QR и подписка → включить подписку`.

### Переключить Inbound

`Xray Server → Inbound → выбрать профиль → заполнить только его параметры → Проверить конфигурацию → Сохранить и применить`.


### Включить второй Hysteria 2 Inbound

1. Откройте `Xray Server → Inbound` и выберите `Hysteria 2`.
2. В блоке Multi-Inbound включите резервный экземпляр.
3. Оставьте предложенный `8443/udp` или укажите другой свободный UDP-порт.
4. Разрешите этот порт в Security Group и firewall.
5. Проверьте и примените конфигурацию.
6. Откройте страницу клиента: там появится вторая ссылка и второй QR-код.
7. Проверьте подключение к каждому порту отдельно.

### Включить весь трафик через WARP

1. `Network → Outbounds` — создать и отдельно проверить WARP.
2. `Network → Traffic Rules` — выбрать режим **«Весь трафик через WARP»**.
3. Проверить и применить конфигурацию.
4. Переподключить клиент и проверить внешний IP.

При использовании `Hysteria 2` клиентскую ссылку, UDP-порт, Auth, TLS и masquerade менять не нужно. Рабочая цепочка выглядит так:

```text
Клиент → Hysteria 2 → Xray → WARP → Интернет
```

Подробная проверка и быстрый возврат на `direct`: [Cloudflare WARP](WARP.md#подтверждённый-сценарий-hysteria-2-через-warp).

### Направить один сайт через WARP

1. создать WARP;
2. выбрать режим **«Только выбранные сайты»**;
3. добавить правило с доменом и целью `warp`;
4. проверить и применить.

### Включить HTTPS панели

`Security → Panel Access → HTTPS + Let's Encrypt`.

Для выпуска сертификата домен должен уже указывать на сервер, а TCP `80` и порт панели должны быть доступны.

## После любого изменения

Проверьте:

1. Xray имеет состояние `active`;
2. `config.json` проходит `xray run -test`;
3. клиент подключается;
4. нужный сайт открывается через ожидаемый Outbound;
5. в журналах нет новых ошибок.
