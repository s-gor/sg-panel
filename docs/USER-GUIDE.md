# Руководство пользователя SG-Panel

Документ относится к версии `v0.10.0-rc80`.

## Первый вход

После установки откройте адрес, показанный мастером:

```text
http://PUBLIC_IP:ПОРТ_ПАНЕЛИ
```

После входа:

1. Откройте `System → Status & Services`.
2. Проверьте Xray, Nginx, SG-Panel и `config.json`.
3. Задайте понятное имя сервера.
4. Проверьте публичный IP или домен.
5. Откройте `Clients`, выберите `sg-admin` и получите первую ссылку.
6. Проверьте подключение до дальнейших изменений.

В верхней панели доступны темы **Графит** и **Латте**. Выбор сохраняется в браузере.

## Как SG-Panel применяет изменения

Формы и JSON-редакторы используют один порядок:

1. изменить параметры;
2. нажать **«Проверить конфигурацию»**;
3. дождаться проверки модели и `xray run -test`;
4. нажать **«Сохранить и применить»**;
5. проверить реальный клиентский трафик.

Проверка выполняется на временной копии данных. Если поле изменилось после проверки, разрешение на сохранение становится недействительным.

## System

### Resources

Показывает CPU, RAM, диск, uptime и ресурсы процессов. Доступная RAM определяется по `MemAvailable`.

### Status & Services

Показывает состояние Xray, Nginx, SG-Panel и итоговой конфигурации. Здесь же редактируется имя сервера и отображается публичный адрес.

### Logs & Diagnostics

Используйте при ошибках запуска, недоступном порте, проблемах сертификата, Cascade или Xray. Не перезапускайте службу многократно без просмотра журнала.

## Clients

### Создать клиента

```text
Clients → Новый клиент → заполнить данные
→ Проверить конфигурацию
→ Сохранить и применить
```

UUID/Auth создаётся и хранится панелью. При переключении серверного профиля идентификаторы клиентов сохраняются.

### Получить ссылку или подписку

1. Откройте клиента.
2. Перейдите к ссылкам, QR и подписке.
3. Используйте активную ссылку текущего профиля.
4. Сохранённые неактивные ссылки предназначены для ранее настроенных, но сейчас не работающих схем.

## Xray Server

SG-Panel поддерживает:

- VLESS REALITY RAW/TCP;
- VLESS XHTTP-REALITY;
- VLESS XHTTP-TLS;
- Hysteria 2;
- смешанный XHTTP-TLS + Hysteria 2.

Для новых REALITY-профилей fingerprint по умолчанию — Firefox. Vision является серверно-клиентской настройкой: Flow должен совпадать в конфигурации и ссылке.

После смены профиля получите новую активную ссылку или обновите подписку.

## Cascade

Cascade соединяет две полные SG-Panel:

```text
Клиент → входной сервер → выходной сервер → Интернет
```

### Быстрая настройка

1. На выходном сервере откройте `Cascade`.
2. Нажмите **«Сделать этот сервер выходом»**.
3. Скопируйте служебную ссылку.
4. На входном сервере вставьте её и нажмите **«Подключить и проверить»**.
5. После успешного IP-теста нажмите **«Включить Cascade»**.
6. Пользователю выдайте обычную ссылку из `Clients` входного сервера.

Routing вручную для основного Cascade не требуется.

Кнопка **«Сделать этот сервер выходом»** на входном сервере после подключения текущей цепочки не нужна. Она предназначена только для использования этого сервера как выхода другой цепочки.

### Отключить или удалить

- **«Отключить и вернуть Direct»** временно возвращает прямой выход и сохраняет параметры Cascade.
- **«Удалить Cascade»** удаляет локальную часть только на текущем сервере.
- Для полной очистки удалите Cascade отдельно на входе и выходе.

Полная инструкция, замена выхода и ошибки: [CASCADE.md](CASCADE.md).

## Cluster и SG-Node

Cluster Controller хранит центральную базу и управляет удалёнными SG-Node. На Node вторая панель не устанавливается.

### Правильный порядок

1. В `Cluster` нажмите **«Скопировать команду полной установки SG-Node»** и запустите её на чистой Ubuntu.
2. После `ready_to_connect` нажмите **«Добавить подготовленную SG-Node»**.
3. Нажмите **«Создать карточку и новый токен»**.
4. На карточке скопируйте отдельную команду подключения и запустите её на Node.
5. Дождитесь Agent, Worker, heartbeat и состояния **«В сети»**.
6. Разрешите `64441/tcp` на Node.
7. В шаге первого профиля выберите клиента и нажмите **«Проверить и развернуть»**.

До первого профиля Xray и Nginx могут показывать **«ожидает первого профиля»** — это штатно.

**«Создать новую команду»** используется только для повторной регистрации или переноса, а не после каждого heartbeat.

Полная инструкция, журналы и ошибки: [MULTI-NODE.md](MULTI-NODE.md).

## Routing

Раздел содержит четыре вкладки:

- `Traffic Rules`;
- `Outbounds`;
- `DNS`;
- `GeoFiles`.

Правила обрабатываются по приоритету. Если ни одно правило не совпало, используется основной выход. При включённом Cascade основным выходом становится Cascade; явные правила всё равно выполняются раньше.

### WARP

Создание WARP Outbound само по себе не меняет трафик. После создания выберите режим и примените правила.

Доступны варианты:

- не использовать WARP;
- только выбранные сайты;
- весь трафик через WARP.

Для российских направлений:

- только доменные зоны — `geosite:tld-ru`;
- российские сайты и IP — отдельные правила `geosite:category-ru` и `geoip:ru`.

`category-ru` уже включает `tld-ru`; дублировать их в одном широком пресете не нужно.

## Security

Раздел управляет:

- HTTP/HTTPS панели;
- публичным портом и доменом;
- Panel exposure;
- паролем и сессиями;
- IP allowlist;
- журналом входов.

Backend SG-Panel слушает localhost, а публичный доступ обслуживает Nginx.

## Maintenance

### Backups

Создавайте резервную копию перед крупными изменениями и скачивайте её на локальный компьютер. Reality private key хранится в базе, поэтому архивы являются секретными.

### Updates

Проверка обновления, установка и rollback выполняются отдельной системной операцией. Кратковременный перезапуск веб-панели не означает остановку процесса обновления.

## После любого изменения

Проверьте:

1. Xray находится в ожидаемом состоянии;
2. `config.json` проходит `xray run -test`;
3. клиент подключается;
4. внешний IP соответствует выбранной схеме;
5. в журналах нет новых ошибок.
