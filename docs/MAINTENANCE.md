# Maintenance, резервные копии и обновления

Раздел `Maintenance` содержит две вкладки:

- `Backups` — создание, проверка, скачивание и восстановление копий;
- `Updates` — раздельная проверка и безопасное обновление SG-Panel и Xray Core, два живых журнала и автоматический откат.

## Когда создавать обычную копию

Создавайте резервную копию перед сменой Inbound-профиля, крупной правкой Traffic Rules или DNS, восстановлением другой копии и ручной работой с полным JSON. SG-Panel также создаёт автоматические точки отката перед опасными операциями.

## Что содержит копия Backups

Обычная копия содержит как минимум:

- SQLite `panel.db`;
- снимок итогового `config.json`;
- метаданные и контрольные суммы.

SQLite хранит клиентов, UUID/Auth, серверные настройки, правила, Outbounds, DNS, WARP, подписки, статистику и параметры безопасности панели.

### Создание и проверка

1. Откройте `Maintenance → Backups`.
2. Нажмите **«Создать резервную копию»**.
3. После создания нажмите **«Проверить»**.
4. Не используйте для восстановления копию, которая не прошла проверку.

Скачайте SQLite и config snapshot на локальный компьютер. Файлы могут содержать приватные ключи, UUID, токены и сетевую конфигурацию.

### Восстановление

При полном восстановлении панель возвращает SQLite, заново формирует рабочий `config.json`, выполняет `xray run -test`, перезапускает Xray и проверяет состояние службы. После восстановления проверьте клиента и Routing-маршруты.

## Maintenance → Updates

Вкладка показывает:

- установленную версию;
- последнюю опубликованную версию;
- дату последней проверки;
- состояние последней операции;
- живой журнал текущего обновления.

### Проверка и установка

1. Откройте `Maintenance → Updates`.
2. Нажмите **«Проверить сейчас»**.
3. Сравните поля **«Установленная версия»** и **«Последняя версия»**.
4. Если доступна более новая версия, нажмите **«Обновить до …»** и подтвердите действие.
5. Следите за этапами в живом журнале: загрузка, проверка пакета, страховочная копия, установка и итоговый контроль.
6. Кратковременная потеря связи со страницей во время перезапуска панели нормальна. Системная операция продолжает работать независимо от браузера.
7. Дождитесь состояния **«Готово»**. После этого обновите страницу и проверьте рабочее подключение клиента.
8. Если показано **«Восстановлено»**, новая версия не была оставлена: updater автоматически вернул предыдущую рабочую версию.

Последняя версия определяется по опубликованным тегам репозитория SG-Panel. Возможны три нормальных результата проверки:

- **обновление доступно** — появляется активная кнопка **«Обновить до …»**;
- **установлена последняя версия** — кнопка установки недоступна, обновлять ничего не требуется;
- **проверка не выполнена** — показывается причина ошибки связи или получения списка версий, текущая установка при этом не изменяется.

Повторный запуск блокируется, пока текущая операция не завершена. Не перезагружайте сервер и не запускайте ручной установщик до появления итогового состояния **«Готово»** или **«Восстановлено»**.

### Обновление Xray Core

На той же странице находится отдельная карточка **Xray Core**. Она не запускает установщик SG-Panel и не меняет SQLite, пользователей, клиентские ссылки, Nginx, HTTPS или сертификаты.

Доступны два независимых канала:

- **Stable** — последний официальный стабильный релиз; предварительные версии игнорируются;
- **Pre-release** — последний официальный предварительный релиз, который можно установить только вручную кнопкой **«Установить для теста»**.

Обычный выбор — **Stable**. Предварительный канал не включается автоматически и предназначен только для осознанной проверки новой версии.

Перед заменой бинарника updater:

1. определяет архитектуру сервера;
2. скачивает архив из официального `XTLS/Xray-core` и соответствующий файл `.dgst`;
3. сравнивает SHA-256;
4. проверяет точную версию нового бинарника;
5. запускает новый бинарник с действующим `config.json` в режиме `run -test`;
6. сохраняет прежний бинарник и снимок конфигурации;
7. перезапускает только службу Xray;
8. проверяет версию, службу и все активные TCP/UDP Inbound;
9. при любой ошибке возвращает прежний бинарник и снова запускает Xray.

Страховочные каталоги обновления Xray находятся в:

```text
/root/sg-panel-backups/YYYYMMDD-HHMMSS-xray-update-rollback
```

SG-Panel блокирует параллельный запуск обновления панели и Xray. После ручного обновления Xray последующие обновления SG-Panel не понижают его до встроенной рекомендуемой версии, если установленный Xray новее.

### Что сохраняет страховочная копия обновления

Перед изменением сервера updater сохраняет:

- файлы текущего приложения;
- согласованную копию SQLite;
- `/etc/xpanel-mvp`, включая `web.env` и режим доступа;
- активный `config.json` Xray;
- клиентов, UUID/Auth, подписки и статистику;
- Inbound, Outbounds, DNS, WARP и Traffic Rules;
- конфигурацию Nginx, SG-заглушку и deploy-hook сертификатов;
- systemd units и состояние основных таймеров;
- копии используемого сертификата и закрытого ключа в страховочном каталоге.

Страховочные каталоги обновлений находятся в:

```text
/root/sg-panel-backups/YYYYMMDD-HHMMSS-update-rollback
```

### Проверки после установки

Updater проверяет:

- локальный `/health` SG-Panel;
- точную установленную версию;
- службу `xpanel-web`;
- `xray run -test` и службу Xray;
- `nginx -t` и службу Nginx, если она была активна;
- maintenance и traffic timers, если они были активны до обновления.

При ошибке восстанавливаются предыдущие файлы приложения, SQLite, env, Xray, Nginx, заглушка и systemd units, после чего службы запускаются в прежнем состоянии.

### Первый переход на RC34

Старая версия SG-Panel не может показать функцию, которой в ней ещё нет. Поэтому первый переход с RC30 на RC34 выполняется обычной установочной командой или из проверенного ZIP. После установки RC34 последующие версии можно устанавливать через `Maintenance → Updates`.

### Запасной ручной способ

Если интерфейс недоступен, распакуйте проверенный новый исходный код и запустите из его корня:

```bash
sudo bash deploy/update-from-local-source.sh
```

Этот способ использует тот же updater, страховочную копию, проверки и rollback. Повторный запуск полного установщика также остаётся запасным вариантом.

## Сертификаты

Let's Encrypt продлевается системным Certbot. После продления deploy-hook обновляет runtime-копии, необходимые Xray TLS/Hysteria.

```bash
sudo certbot certificates
systemctl list-timers | grep -i certbot
```

## Основные службы

```bash
systemctl status xpanel-web
systemctl status xray
systemctl status nginx
systemctl status xpanel-traffic.timer
systemctl status xpanel-maintenance.timer
```

## Основные пути

```text
/opt/xpanel-mvp
/opt/xpanel-mvp/data/panel.db
/usr/local/etc/xray/config.json
/etc/xpanel-mvp/web.env
/etc/xpanel-mvp/panel-access.env
/var/lib/sg-panel-update
/root/sg-panel-backups
```

## Небольшой сервер

На машине с 1 ГиБ RAM файловый кэш может занимать значительную часть памяти — это нормально. Оценивайте `MemAvailable`, swap activity и состояние процессов. Не очищайте Linux cache по расписанию: это обычно ухудшает работу.
