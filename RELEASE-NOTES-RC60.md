# SG-Panel v0.10.0-rc60

RC60 собран на основе `059-SG-Panel-RC59.zip`. Главная задача релиза — сделать каскад между двумя SG-Panel понятной самостоятельной функцией, а не скрытой комбинацией Outbounds и выхода по умолчанию.

## Отдельный раздел «Каскад»

В главном меню появился самостоятельный раздел **«Каскад»** с наглядной схемой:

```text
Клиент → CC1 · входной сервер → CC2 · выходной сервер → Интернет
```

Пользователю больше не требуется вручную понимать технические `tag`, `default outbound` и разницу между «Outbound активен» и «трафик действительно идёт через него».

## Пошаговый мастер

1. На CC2 создаётся отдельный служебный клиент `Cascade-CC1-to-CC2`.
2. Его VLESS REALITY-ссылка вставляется в раздел «Каскад» на CC1.
3. SG-Panel автоматически создаёт или обновляет управляемый VLESS Outbound.
4. Выполняется полноценная проверка `CC1 → VLESS REALITY → CC2 → Internet`.
5. Панель показывает реальный выходной IP, страну, Cloudflare colo и наличие WARP на CC2.
6. Кнопка «Включить каскад» становится доступна только после успешной полной проверки.
7. Кнопка отключения безопасно возвращает основной выход на `direct`.

## Полная проверка вместо одного TCP

Кнопка проверки временно запускает отдельный локальный Xray с SOCKS-входом и импортированным Outbound. Запрос выполняется через настоящий UUID, REALITY Public Key, Short ID, SNI, fingerprint и Flow.

Рабочий Xray и текущие пользователи во время проверки не переключаются.

Если параметры выходного сервера изменены после проверки, результат автоматически помечается устаревшим и включение каскада блокируется до повторного теста.

## Безопасность переключения

- Вставленная VLESS-ссылка не сохраняется целиком.
- При замене выходного сервера активный каскад сначала возвращается на `direct`.
- Новый выход требует повторной полной проверки.
- Отключение каскада не удаляет Outbound и не затрагивает клиентов.
- Ручные Outbounds и Traffic Rules остаются в Routing как экспертный режим.
- Явные Routing rules по-прежнему выполняются раньше основного выхода.

## Совместимость

Существующие `cascade-*` Outbounds из RC59 автоматически обнаруживаются. Если они уже были вручную назначены выходом по умолчанию, раздел показывает фактическое состояние, но просит выполнить полноценную проверку.

WARP, Cluster, managed profile v2, клиенты, UUID, ключи, сертификаты и SG Client не изменялись.
