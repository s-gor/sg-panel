# SG-Panel v0.10.0 RC42 — Saved Client Links and Live Installer

RC42 улучшает клиентские ссылки и полностью перерабатывает вывод установщика без изменения сетевых профилей RC41.

## Клиентские ссылки

- Multi-Inbound URI получают короткие имена: `Client/Primary`, `Client/Backup`, `Client/Alt`.
- Страница клиента разделена на «Активные сейчас» и «Сохранённые, но неактивные».
- Ссылки других сохранённых профилей больше не исчезают при переключении схемы сервера.
- Неактивную ссылку можно скопировать, но интерфейс явно предупреждает, что она заработает только после активации соответствующего профиля.
- Постоянная подписка по-прежнему содержит только реально активные соединения.

## Установщик

- На новой установке пароль администратора и его повтор запрашиваются первыми.
- Все остальные параметры также собираются до начала системных изменений.
- После запуска установки дополнительные вопросы не задаются.
- Добавлены три понятных этапа и одна живая строка с вертушкой и временем выполнения.
- Вывод `apt`, `dpkg`, установщиков, Python и systemd направляется в постоянный журнал.
- При ошибке показывается короткое сообщение и последние строки журнала.
- Тот же стиль используется при обновлении уже установленной SG-Panel.

## Совместимость

- Основа: RC41 Hotfix 2.
- UUID, Hysteria auth, REALITY Short ID, XHTTP Path, порты, сертификаты и активный профиль не изменяются.
- Xray новее рекомендуемой версии не понижается.

## Hotfix 1: три REALITY вместе с HTTPS fallback

В первоначальном RC42 третий публичный REALITY использовал `TCP/9443`, но этот же номер был занят локальной HTTPS-заглушкой REALITY на `127.0.0.1:9443`. При включении третьего Inbound возникал конфликт bind, из-за которого тройная схема не запускалась.

Hotfix сохраняет публичный `TCP/9443` для третьего REALITY и переносит только внутреннюю заглушку на `127.0.0.1:10443`. Существующие установки мигрируют автоматически. Клиентские ссылки, UUID, ключи, Short ID и публичные порты не меняются.

## Hotfix 2: Multi-REALITY с XTLS Vision

Тест на реальной EC2 подтвердил: один REALITY с Vision работает, три REALITY без Vision работают, но несколько независимых REALITY Inbound с Vision одновременно не работают. Это соответствует известному поведению Xray для множества Vision Inbound.

Hotfix меняет архитектуру только для режима Vision:

- при одном активном REALITY сохраняется обычный одиночный Inbound;
- при двух или трёх активных точках создаётся один Xray REALITY/Vision Inbound;
- все активные Short ID входят в общий `realitySettings.shortIds`;
- без HTTPS один Inbound слушает список публичных TCP-портов;
- при HTTPS Nginx публикует `443`, `8443`, `9443` и передаёт REALITY-трафик в один внутренний Xray listener;
- клиентские ссылки, порты, UUID и Short ID не меняются;
- при отключённом Vision остаются отдельные REALITY Inbound.

Так сохраняются три независимые клиентские ссылки `Primary`, `Backup`, `Alt`, но устраняется сама причина сбоя Vision.
