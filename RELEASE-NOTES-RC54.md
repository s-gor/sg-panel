# SG-Panel v0.10.0-rc54

## Guided SG-Node onboarding

RC54 собран только на основе подтверждённого `053-SG-Panel-RC53.zip`. SG Client не входит в архив и не изменяется. Managed profile v2, Vision, Routing, GeoFiles и Panel exposure сохранены.

### Новый порядок Cluster

Раздел Cluster больше не начинает работу с неоднозначной большой кнопки «Добавить ноду». Вместо неё показан мастер из пяти этапов:

1. полная подготовка чистой Ubuntu без токена;
2. создание карточки подготовленной SG-Node и одноразового токена;
3. отдельная команда подключения;
4. проверка Agent, Worker, heartbeat, адреса и версий;
5. первое развёртывание VLESS REALITY RAW/TCP `64441`.

Установочная и connect-команды — отдельные самодостаточные строки. Они сами обеспечивают минимальный bootstrap через `apt-get`, загружают нужный скрипт во временный файл, проверяют `bash -n` и удаляют временный файл после выполнения.

Connect-скрипт не пытается имитировать полную установку. Без `/etc/sg-node/install.env` и состояния `ready_to_connect` он прекращает работу с понятным сообщением.

### Node status и публичный адрес

Heartbeat теперь передаёт независимые версии и состояния Agent и Worker. Controller сохраняет публичный адрес из metadata, а при его отсутствии может безопасно использовать глобальный адрес запроса. Для NAT или нестандартного reverse proxy добавлено ручное поле публичного IPv4/домена.

### Первый профиль SG-Node

Подтверждённая стартовая схема мастера:

- VLESS REALITY;
- RAW/TCP;
- `64441/TCP`;
- `xtls-rprx-vision`;
- fingerprint `firefox`.

Worker сохраняет прежний безопасный цикл: проверка payload и SHA-256, `xray run -test`, backup, атомарная замена, проверка службы и rollback при ошибке.

### Firefox для новых REALITY-профилей

`firefox` стал новым значением по умолчанию во всех путях создания REALITY-профиля: UI, CLI, DB defaults, normalisation и Node deployment. Миграция не переписывает существующие сохранённые значения `chrome` или другие допустимые fingerprint.

### Исправление RAM

В System → Status & Services подпись RAM раньше соединяла процент использования памяти со значением свободного места на диске. RC54 показывает `memory_available`, поэтому процент и доступный объём относятся к одной и той же RAM.

### Версии Node

- SG-Node Agent: `0.5.0`;
- SG-Node Worker: `0.5.0`;
- connect script: `1.1`.

## Совместимость и обновление

Обновление сохраняет существующие клиенты, UUID, ключи REALITY, Short ID, сертификаты, Flow, fingerprint, server settings и managed profile v2. Новые поля Node добавляются миграцией SQLite без удаления прежних данных.

Новый enrollment token создаётся из карточки Node. Создание новой команды отзывает предыдущий неиспользованный token этой Node; раскрытый token нельзя считать действующим после перевыпуска. Исходный архив не содержит runtime-базу Controller и поэтому не может удалённо перевыпустить token на уже работающем сервере.

## Проверки сборки

Локально выполнены:

- SHA-256 исходного RC53;
- Python compile;
- `bash -n` для installer/connect/update scripts;
- 472 pytest-теста и 2 subtests;
- отдельные проверки мастера Cluster, однострочных команд, token rotation, `ready_to_connect`, public-address fallback, Agent/Worker status, Firefox defaults, сохранения существующего Chrome и исправления RAM.

Чистая установка на реальных EC2/Ubuntu, реальный клиентский трафик, перезапуск удалённых служб и rollback после искусственной ошибки должны быть повторены на тестовых серверах до публикации GitHub Release.

## Не включено в RC54

TOTP MFA, подробная процедура Cloudflare, доступ к панели только через SSH localhost и разделение административного UI/Cluster API оставлены отдельными будущими задачами.
