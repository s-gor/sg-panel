# SG-Panel v0.10.0 RC30

SG-Panel — компактная self-hosted веб-панель для управления Xray на собственном сервере.

Панель хранит настройки в SQLite и формирует итоговый `config.json`. Все изменяющие Xray операции работают по обязательной последовательности:

```text
Редактирование формы или JSON
        ↓
Проверить конфигурацию
        ↓
Временная копия SQLite
        ↓
Проверка модели SG-Panel и xray run -test
        ↓
Сохранить и применить
```

Рабочая база и запущенный Xray не изменяются во время проверки. Любое изменение полей после успешной проверки снова блокирует сохранение. Результат проверки подписан, действует ограниченное время и становится недействительным, если конфигурация панели была изменена в другой вкладке или другим администратором.

## Главное в RC30

RC30 объединяет несколько крупных этапов развития SG-Panel после опубликованного RC9.

### Hysteria 2

В панели появился отдельный **Hysteria Studio**: профиль `Hysteria 2 + TLS` поверх QUIC/UDP, проверка до применения, QUIC-пресеты, настройка скорости, port hopping, masquerade, ссылка, QR-код и подписка.

### Установка без обязательного домена

Первую установку можно выполнить по публичному или локальному IP. Панель запускается по HTTP на отдельном выбранном порту, а домен и HTTPS подключаются позже в разделе **Безопасность → Доступ к панели**. Для начального `RAW/TCP + REALITY` собственный домен и сертификат не нужны.

### Clients & Traffic Studio

Раздел Clients теперь объединяет сводку, поиск, фильтры, сортировку, карточку клиента, сроки, online-состояние, последнюю активность, ссылки, QR-коды, подписки и конфигурации.

Пользовательская статистика сохраняется в SQLite: текущая сессия Xray, сегодня, текущий месяц, всё время, текущая скорость и график за 14 дней. История не пропадает после перезапуска Xray, обновления панели или перезагрузки сервера.

### Безопасный сброс трафика

В карточке клиента находится кнопка **«Сбросить трафик клиента»**, а в верхней панели Clients — **«Сбросить весь трафик»**. Обе операции требуют подтверждения и не удаляют клиента, UUID/Auth, ссылку, подписку или конфигурацию.

RC30 также включает автоматическую активацию и строгую проверку Xray Stats API, Xray `v26.5.9`, обязательную проверку конфигурации до сохранения, резервные копии и автоматический откат.

## Основные возможности

- `RAW/TCP + REALITY`;
- `XHTTP + TLS`;
- `XHTTP + REALITY`;
- `Hysteria 2 + TLS` поверх QUIC/UDP;
- Cloudflare WARP для всего или части трафика;
- Clients & Traffic Studio: пользователи, UUID/Auth, сроки, поиск, фильтры, ссылки и QR-коды;
- долговременная статистика SQLite: сессия, сегодня, месяц, всё время, скорость и 14-дневный график;
- персональные подписки;
- Outbounds, Routing и DNS;
- контекстные JSON-редакторы Users, Inbound, Outbounds, Routing, DNS и WARP;
- полный редактор `config.json`;
- обязательная проверка на временной SQLite-копии через `xray run -test`;
- проверяемые резервные копии, полное восстановление config.json и автоматический откат;
- пароль, активные сессии, IP allowlist и журнал входов;
- начальная установка по IP без DNS;
- позднее включение HTTPS с Let's Encrypt.

## Сетевые режимы

| Профиль | Публичный порт `443` | Сертификат Xray | Flow |
|---|---|---|---|
| `RAW/TCP + REALITY` | Xray | не используется | `xtls-rprx-vision` |
| `XHTTP + TLS` | Nginx, затем Xray `127.0.0.1:8443` | Let's Encrypt | отсутствует |
| `XHTTP + REALITY` | Xray | не используется | отсутствует |
| `Hysteria 2 + TLS` | Xray `443/udp` | Let's Encrypt | не используется |

HTTPS самой панели и TLS для `XHTTP + TLS` — разные настройки. Начальный `RAW/TCP + REALITY` не требует собственного домена или сертификата.

## Требования

Первоначальная установка больше не требует домена, DNS-записи или сертификата; HTTPS включается позже в разделе **Безопасность → Доступ к панели**.

- Ubuntu Server;
- `sudo` или `root`;
- минимум 1 ГиБ RAM;
- доступный IP или hostname сервера;
- открытый TCP `443` для начального Reality Inbound;
- для Hysteria 2 дополнительно открывается выбранный UDP-порт;
- отдельный TCP-порт панели из диапазона `49152–65535`.

Для первоначальной установки не требуются:

- домен;
- DNS-запись;
- TCP `80`;
- сертификат Let's Encrypt.

Они понадобятся только при последующем включении HTTPS.

## Порты

| Порт | Назначение | Доступ извне |
|---:|---|---|
| `22/tcp` | SSH | только ваш IP |
| `443/tcp` | VLESS Inbound | клиенты Xray |
| `443/udp` | Hysteria 2 Inbound, когда выбран этот профиль | клиенты Hysteria 2 |
| `61443/tcp` | HTTP или HTTPS панели | только ваш IP или локальная сеть |
| `8080/tcp` | backend SG-Panel | не открывать |
| `8443/tcp` | локальный Xray для `XHTTP + TLS` | не открывать |
| `80/tcp` | HTTP-01 Let's Encrypt | открыть только при включении HTTPS |

## Быстрая установка

```bash
sudo apt-get update && sudo apt-get install -y curl ca-certificates unzip && curl -fsSL https://raw.githubusercontent.com/s-gor/sg-panel/main/install-from-github.sh -o /tmp/install-sg-panel.sh && bash -n /tmp/install-sg-panel.sh && chmod 700 /tmp/install-sg-panel.sh && sudo bash /tmp/install-sg-panel.sh
```

Не используйте `curl | bash`: мастер должен читать ответы с клавиатуры.

Установщик автоматически попробует определить публичный IPv4 EC2 и запросит:

```text
Адрес Xray для клиентов (публичный IP или домен)
Публичный HTTP-порт панели [61443]
Имя первого пользователя [sg-admin]
Reality target [www.bing.com:443]
Reality SNI [www.bing.com]
Пароль администратора панели
```

Для EC2 установщик предлагает публичный IPv4. Для домашней VM — локальный IPv4.

Во время установки каждый этап отображается одной обновляемой строкой с одной зелёной вращающейся палочкой и заменяется на `Готово`. После завершения установщик печатает итоговый адрес:

```text
http://SERVER_IP:61443
```

Первую прямую ссылку текущего Inbound-профиля можно показать командой:

```bash
sudo cat /root/sg-panel-first-user.txt
```

## Включение HTTPS позже

1. Создайте DNS-запись `A` на публичный IPv4 сервера.
2. Разрешите TCP `80` и выбранный порт панели.
3. Откройте `Безопасность → Доступ к панели`.
4. Выберите `HTTPS + Let's Encrypt`.
5. Введите домен и порт.
6. Нажмите **«Сохранить и применить»**.
7. Следите за живым журналом операции.
8. После переключения браузер автоматически откроет новый HTTPS-адрес. Если браузер заблокировал переход, используйте показанную кнопку ручного открытия.

Порт `443` остаётся доступен для Xray Reality; панель использует отдельный выбранный порт.

Вернуться с HTTPS на HTTP можно в том же разделе.

## Доступ только через SSH-туннель

Публичный порт панели можно не открывать в firewall. На рабочем компьютере:

```bash
ssh -L 61443:127.0.0.1:61443 user@SERVER_IP
```

Затем откройте:

```text
http://127.0.0.1:61443
```

## Обновление

Повторно запустите установочную команду. Установщик:

- обнаружит существующую SG-Panel;
- сохранит SQLite, пользователей, UUID и ключи;
- сохранит текущий HTTP или HTTPS режим;
- не попросит домен заново;
- создаст резервную копию;
- выполнит rollback при ошибке.

Параметр `--reconfigure` теперь меняет только адрес Xray и базовые Reality-параметры. Доступ к панели меняется в интерфейсе.

```text
/opt/xpanel-mvp                         приложение
/opt/xpanel-mvp/data/panel.db           SQLite
/opt/xpanel-mvp/data/panel-access-jobs  журналы переключения HTTP/HTTPS
```

## Безопасность

- не открывайте `8080/tcp` и `8443/tcp`;
- ограничьте SSH и порт панели своим IP;
- HTTP используйте в локальной сети или через SSH-туннель;
- для публичного постоянного доступа включите HTTPS;
- не публикуйте приватные ключи, токены подписок и резервные копии.

## Удаление

Обычное удаление безопасно по умолчанию: оно удаляет SG-Panel и её службы, но сохраняет Xray, Nginx, сертификаты и резервные копии.

```bash
curl -fsSL https://raw.githubusercontent.com/s-gor/sg-panel/main/deploy/uninstall.sh -o /tmp/uninstall-sg-panel.sh && bash -n /tmp/uninstall-sg-panel.sh && chmod 700 /tmp/uninstall-sg-panel.sh && sudo bash /tmp/uninstall-sg-panel.sh
```

Полная очистка одноразового тестового сервера выполняется только отдельным `deploy/purge-test-server.sh`.
