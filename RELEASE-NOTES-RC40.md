# SG-Panel v0.10.0 RC40 — Mixed XHTTP + Hysteria 2

RC40 продолжает Multi-Inbound и добавляет отдельный профиль, в котором XHTTP и Hysteria 2 работают одновременно.

## Hotfix 1 — названия профилей и сводка

В интерфейсе используются короткие и однозначные названия профилей:

- `VLESS REALITY`;
- `VLESS XHTTP-TLS`;
- `VLESS XHTTP-REALITY`;
- `Hysteria 2`;
- `XHTTP-TLS + Hysteria 2`.

Верхняя сводка показывает фактическое количество активных XHTTP-TLS и Hysteria 2 Inbound, а также реальные TCP/UDP-порты. Настройки сервера и клиентские ссылки не изменяются.

## Схема

```text
TCP/443 → Nginx → XHTTP Path 1 → 127.0.0.1:8443/tcp
                  XHTTP Path 2 → 127.0.0.1:8444/tcp
                  XHTTP Path 3 → 127.0.0.1:8445/tcp

UDP/443  → Hysteria 2 основной
UDP/8443 → Hysteria 2 резервный
UDP/9443 → Hysteria 2 дополнительный
```

Одинаковый номер `8443` допустим: XHTTP использует TCP на loopback, Hysteria 2 использует публичный UDP.

## Совместимость

- существующий основной XHTTP Path и UUID пользователей сохраняются;
- дополнительные XHTTP Path остаются стабильными;
- основной Hysteria auth и дополнительные auth сохраняются;
- клиентские URI не меняют секретные данные;
- отдельные профили `VLESS XHTTP-TLS` и `Hysteria 2` остаются доступными;
- установленный Xray новее рекомендуемой версии не понижается.

В смешанном `config.json` основной XHTTP сохраняет tag `vless-reality-in`. Основной Hysteria получает внутренний tag `hysteria2-primary-in`, чтобы два Inbound не конфликтовали. Это не меняет клиентскую ссылку или auth.

## Интерфейс

Карточки Multi-XHTTP получили адаптивную раскладку. Path расположен отдельной строкой, Listen и локальный порт — следующей. На меньшей ширине карточки переходят с трёх колонок на две и затем на одну без наложения текста.

## Проверка после установки

1. Сначала убедитесь, что прежний выбранный профиль продолжает работать.
2. Выберите `XHTTP-TLS + Hysteria 2`.
3. Выполните обязательную проверку и примените конфигурацию.
4. Проверьте минимум одну XHTTP-ссылку и одну Hysteria 2-ссылку.
5. Затем проверьте остальные активные экземпляры и общую подписку.

Дополнительные Hysteria UDP-порты должны быть открыты в AWS Security Group. Локальные XHTTP TCP-порты наружу не открываются.
